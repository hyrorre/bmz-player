# 書庫内の複数フォルダ・深い階層を選曲で辿る

## 初回実装（e3e9ce4f）

開始時のHEADは`7a19ad32`。書庫のスキャンは既に全階層の譜面を登録しており、
1フォルダ・2階層という読み取り制限はなかった。
選曲の`beatoraja_folder_listing`が書庫内のフォルダ行を削除するため、
複数グループに分かれた深い譜面へフォルダ移動で到達できなかった。
また、直下に譜面がある場合や浅い曲フォルダと深いグループが混在する場合も、配下が隠れていた。

書庫内はBMZ拡張として、各階層の譜面と子フォルダを併記する。
曲フォルダの譜面を親へ直接並べるのは、配下に別の譜面フォルダがない場合だけにした。
単一の内包フォルダがある場合の書庫の段の省略は維持する。
通常フォルダのbeatoraja互換の表示規則は維持する。

譜面数・ランプ・フォルダオートプレイは共通の到達可能フォルダ判定を使い、
書庫自身の譜面と深い配下を重複なく集める。深い階層の集計は明示的なスタックで辿る。
「同一曲フォルダ」操作は選択譜面と同じフォルダの譜面だけに限定する。
スキャン・DB schema・譜面識別子・資源の読み取りには変更がなく、既存登録の再スキャンは不要。

仕様は[書庫内譜面](../../docs/archive-songs.md#選曲画面のフォルダ構成)と
[曲フォルダの一覧](../../docs/select-folders.md#曲フォルダの一覧)へ反映した。

## 検証

回帰テストは、複数グループ、直下譜面と深い配下の混在、全対応拡張子のwrapper表示、
32階層の選曲・到達可能フォルダ、ランプ集計、書庫内の通常ディレクトリ名を確認する。
ZIP / solid 7zの実書庫で非再帰rootからのスキャン・深い譜面の読み取りを確認し、
app経路では連続オートプレイと同一曲フォルダ操作を確認する。

Linux x86_64 / Rust 1.100.0で次を実行した。

- `cargo fmt --check`: 成功。
- `cargo check -p bmz-player --locked`: 成功。
- `cargo clippy -p bmz-player --all-targets --locked -- -D warnings`: 成功。
- `LANGUAGE=ja_JP.UTF-8 cargo test -p bmz-player --locked`: 3,233成功、失敗0、66 ignored。

初回実行では、追加した集計テストの期待値の順序に誤りがあり修正した。
変更箇所以外では、未初期化の同梱スキンと英語環境で日本語を期待するテストが失敗したため、
固定された3つのスキンsubmoduleを取得し、日本語設定で全体を再実行して成功した。
GUIでの手動操作・実機再生は未実施。

## 同日追記: 緩和を子フォルダ行の禁止だけに限定

ユーザーの指定に合わせ、書庫内もbeatoraja互換の曲フォルダ規則を適用する。
譜面を含むフォルダは自身の譜面だけを表示し、それより下は辿らない。
子の曲フォルダは配下の有無にかかわらず親へ譜面を直接並べ、
直下に曲フォルダがある一覧では並列する深いグループを表示しない。
緩和するのは「書庫内には子フォルダ行を作らない」という制限だけとし、
譜面の無い中間階層には通常フォルダと同様に子フォルダ行を作る。
ランプ集計・フォルダオートプレイも同じ表示範囲へ戻す。
同一曲フォルダ専用の追加フィルターは不要になるため削除した。

32階層のテストは末端にのみ譜面がある構成に変更した。
書庫直下の譜面、曲フォルダ配下の差分、浅い曲と深いグループの混在が
従来の規則どおり隠れることを確認する。ZIP / solid 7zのスキャンでは配下の差分も
登録される一方、到達可能フォルダ・ランプ・連続オートプレイには含まれないことを確認する。

### スキャンで曲フォルダ配下を省く案

今回はスキャナーを変更していない。実測による速度比較も未実施。

- native走査は`storage/scan/discovery.rs`の`list_directory`で子ディレクトリを集め、
  `read_trees`で次の階層へ進む。曲フォルダが判明した時点で子へ進まなければ、
  画像・音源ディレクトリ等の`read_dir`やファイル種別確認を減らせる。
  曲フォルダ自身の全エントリの列挙は必要で、平坦な構成では効果が小さい。
- Everythingはroot以下をまとめて検索するので、後段で配下を除外しても検索自体は省けない。
  配下に譜面がある場合のimport・DB処理は削減できる。
- 書庫はインデックスの検査や世代確認が必要で、solid書庫は必要なエントリまでの
  順次復号も必要。登録対象を減らすだけでは、書庫の読み取り全体は省けない。
  現在の`scan_charts`も全譜面を読み取るため、対象をデコード前に絞る変更が別途必要になる。
- 配下の譜面を登録しなくなると、検索・難易度表から使える譜面の範囲が変わる。
  通常root・部分スキャン・重複root間の整合性と既存登録のprune方針も決める必要がある。
- 現在の選曲はDBへ正常に取り込まれた譜面の有無で曲フォルダを判定する。
  ファイル名だけでスキャンを止めると、読み込みに失敗する譜面がある場合にも配下を省くため、
  判定をどの段階で行うかも整理が必要になる。

追記分もLinux x86_64 / Rust 1.100.0でfmt・crate check・all-targets Clippyが成功。
`LANGUAGE=ja_JP.UTF-8 cargo test -p bmz-player --locked`は3,233成功、失敗0、66 ignored。
同梱スキン3つは固定されたsubmoduleを使用した。GUIでの手動操作・実機再生は未実施。
