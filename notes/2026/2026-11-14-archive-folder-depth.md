# 書庫内の複数フォルダ・深い階層を選曲で辿る

## 調査と変更

開始時のHEADは`7a19ad32`。書庫のスキャンは既に全階層の譜面を登録しており、
1フォルダ・2階層という読み取り制限はなかった。
選曲の`beatoraja_folder_listing`が書庫内のフォルダ行を削除するため、
複数グループに分かれた深い譜面へフォルダ移動で到達できなかった。
また、直下に譜面がある場合や浅い曲フォルダと深いグループが混在する場合も、配下が隠れていた。

書庫内はBMZ拡張として、各階層の譜面と子フォルダを併記する。
曲フォルダの譜面を親へ直接並べるのは、配下に別の譜面フォルダがない場合だけにした。
単一の内包フォルダがある場合の書庫の段の省略は維持する。
通常フォルダのbeatoraja互換の表示規則は維持する。

譜面数・ランプ・フォルダオートプレイは共通の到達可能フォルダ判定を使い、
書庫自身の譜面と深い配下を重複なく集める。深い階層の集計は明示的なスタックで辿る。
「同一曲フォルダ」操作は選択譜面と同じフォルダの譜面だけに限定する。
スキャン・DB schema・譜面識別子・資源の読み取りには変更がなく、既存登録の再スキャンは不要。

仕様は[書庫内譜面](../../docs/archive-songs.md#選曲画面のフォルダ構成)と
[曲フォルダの一覧](../../docs/select-folders.md#曲フォルダの一覧)へ反映した。

## 検証

回帰テストは、複数グループ、直下譜面と深い配下の混在、全対応拡張子のwrapper表示、
32階層の選曲・到達可能フォルダ、ランプ集計、書庫内の通常ディレクトリ名を確認する。
ZIP / solid 7zの実書庫で非再帰rootからのスキャン・深い譜面の読み取りを確認し、
app経路では連続オートプレイと同一曲フォルダ操作を確認する。

Linux x86_64 / Rust 1.100.0で次を実行した。

- `cargo fmt --check`: 成功。
- `cargo check -p bmz-player --locked`: 成功。
- `cargo clippy -p bmz-player --all-targets --locked -- -D warnings`: 成功。
- `LANGUAGE=ja_JP.UTF-8 cargo test -p bmz-player --locked`: 3,233成功、失敗0、66 ignored。

初回実行では、追加した集計テストの期待値の順序に誤りがあり修正した。
変更箇所以外では、未初期化の同梱スキンと英語環境で日本語を期待するテストが失敗したため、
固定された3つのスキンsubmoduleを取得し、日本語設定で全体を再実行して成功した。
GUIでの手動操作・実機再生は未実施。
