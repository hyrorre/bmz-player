# 不可視ノーツ表示

beatoraja の `LaneRenderer` は `showhiddennote` が有効なとき、不可視ノーツを譜面上の時刻までレーンに描く。標準の描画ではオレンジ色の枠を使い、設定は既定で無効になっている。

BMZ の設定はプロファイルに保存し、プレイ開始時に読み込む。不可視ノーツを既存のノーツ座標計算で描画用スナップショットに追加し、標準プレイフィールドとスキン定義によるプレイフィールドの両方で枠を描く。判定・スコア・キー音は従来の譜面イベントを参照する。

プラクティスでは範囲外のノーツをキー音用の不可視ノーツに変換するため、描画時には区間切り出し前から不可視だったノーツの ID を照合する。譜面変換後もレーンに残る不可視ノーツが表示対象になる。ID の集合は描画キャッシュではなくセッションに持たせる。描画キャッシュは譜面の差し替えで作り直すため、キャッシュに置くと集合が消えて、隠したノーツまで表示されてしまう。

AUTO SCRATCH のノーツを隠す設定では、スクラッチレーンの不可視ノーツも表示しない。

操作と保存先は [設定ガイド](../../docs/settings.md#プレイ) を参照。

## PR #156 のレビュー対応

区間切り出し前の譜面を持つ `PlayfieldProjection` をプラクティス用の譜面で更新する回帰テストに変更した。実プレイと同じ更新経路でキャッシュを再生成し、元の不可視ノーツと区間内の通常ノーツが表示され、区間外の通常ノーツが表示されないことを確認した。設定ガイドでは「不可視ノーツ表示」を「表示」セクションの末尾として案内する。

## PR #154 の描画レビュー対応

スキンの不可視ノーツ枠をレーン本来の矩形から描き、スキン全体の移動・拡縮を枠の四辺にも適用した。
標準・スキン両方で、同時刻の地雷の手前、後続の地雷の背後に枠を描く。半透明の枠は四隅を一度ずつ合成する。

Windows で修正前に4本の描画テストが失敗し、修正後にすべて成功した。
GPU のオフスクリーンテストでは全体を右へ10%移動し、青い地雷に重ねた不透明度50%の枠を読み戻した。
上辺・左辺・角の画素が一致し、枠の内側には地雷の青が残ることを確認した。
この修正を含む workspace 全体で fmt、check、全ターゲットの Clippy（`-D warnings`）、テストが成功した。
