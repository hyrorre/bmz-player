# 空フォルダへの選曲遷移と入力時再読み込みの修正

対象: Issue #28。Windows v0.4.3で、NEW → TODAYや空の曲ルートを開くと
ホイールが消え、その状態で入力すると大きく停止するという報告への対応。

## 原因と変更

- `enter_or_play_selected` は移動先の項目数を確認する前に履歴を更新し、空の一覧を適用していた。
- `move_selection_with_duration` / `enter_or_play_selected` は一覧が空だと毎回同期再読み込みしていた。
  仮想フォルダは全譜面とスコア等を取得してから条件を評価するため、結果が空でも読み込み費用が発生する。
- 遷移を `prepare_select_list` で準備し、表示項目がある場合だけ一覧・カーソル・履歴・
  解決済みモードフィルターを適用する。読み込んだ一覧はそのまま再利用する。
- 空の移動先は現在の表示を維持して通知する。読み込みエラーは空と区別して表示を維持する。
  通常フォルダ・仮想フォルダ・検索履歴・同一フォルダ表示に同じ処理を使用する。
- 検索も完成した一覧を使って成否を判断し、事前の件数照会による二重読み込みを除去した。
  検索失敗時は履歴を追加せず、エラーの場合は入力文字列を保持する。
- 更新で現在のフォルダが空になった場合は最寄りの非空の親へ戻る。親での選択は
  フォルダの識別子を優先し、項目が消えた場合は保存位置を一覧の範囲内に補正する。
- 空一覧での移動・決定は再読み込みせずに終了する。
- 子フォルダ・未所持譜面・設定・コース作成等は有効な表示項目として維持する。
  既存のキーモード自動切り替えも空判定より先に適用する。第三者スキンは変更しない。

現在の契約は [select-folders.md](../../docs/select-folders.md#空フォルダと一覧更新)、
操作は [controls.md](../../docs/controls.md#選曲画面) を参照。

## 検証

- 回帰テスト11件: 空TODAY・空の実フォルダ、非譜面項目、未所持譜面、モード切り替え、
  壊れた定義、最後のお気に入り解除、複数階層の復帰、カーソル復元、親の読み込み失敗、
  空ルートでの終了条件を確認。移動先の読み込みが一度だけであることも確認。
- サンドボックス内ではテスト用DBの準備でアクセス拒否が発生したため、通常権限で再実行して11件成功。
- `cargo fmt --check`、`cargo check -p bmz-player --locked`、
  `cargo clippy -p bmz-player --all-targets --locked -- -D warnings` 成功。
  incremental cacheのhard-link失敗によるcopy fallback警告は環境由来で、ソースのlint警告ではない。
- `cargo test -p bmz-player --locked`: 2,211件成功、19件ignored、失敗なし。ログは
  `.local/issue28-tests.log`（Git管理外）。
- `cargo build -p bmz-player --locked` 成功。
- Windowsの独立データ環境 `.local/issue28-native`、debugビルド、Dx12、120 FPS設定、
  デフォルトスキン、譜面0件で画面を確認。空の通常フォルダと NEW → TODAY のクリックで
  通知が表示され、一覧とカーソルが維持された。続くマウスホイール操作と右クリックによる
  親への復帰も確認した。親では NEW にカーソルが戻る。検証アプリは正常終了済み。
- スクロール操作を含む120フレームのログ（2026-10-06 02:36:05 JST）は、平均input処理
  0.034 ms、平均render 4.285 ms、平均surface待ち0.036 ms、平均present 0.191 ms、
  total redrawのp99 9.780 ms / max 10.569 ms。これは描画処理の内訳で入力遅延そのものではない。
  対応する5秒のCPU frame cadenceは平均8.467 ms、p99約10.239 ms、最大10.695 ms。
  ログは `.local/issue28-native/stderr.log`。修正前との比較や大規模ライブラリの計測は未実施であり、
  この値から性能の改善率や実際の表示間隔は主張しない。

キーボード長押し、ゲームパッド、外部スキン、macOS / Linuxの実機確認は未実施。
空状態での入力による再読み込み除去はコード経路、読み込み回数と状態遷移は自動テストで確認した。
