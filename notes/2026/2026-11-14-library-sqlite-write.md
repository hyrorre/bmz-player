# ライブラリDBの圧縮・同一内容の更新・WAL計測

[直前の計測](2026-11-14-library-scan-note-lookups.md)を受け、Windowsのリリースビルドを
`--locked --offline --no-default-features` で作り、ネイティブ探索で計測した。
実ライブラリは10ルート・128,479件。設定とDBを試行ごとのフォルダにコピーした。

## 1. 譜面統計を圧縮保存

密度分布、速度変化、レーン別集計を、圧縮後のほうが短い場合に限り、1バイトの形式番号を付けた
DEFLATEのBLOBで保存する。既存のTEXTと同居できる。既存の全行を書き換えるmigrationやimport
versionの変更は行わない。旧版への切り戻しはDBの復元、または旧版での強制再読み込みが必要。

| 指標 | 基準 | 圧縮 |
| --- | ---: | ---: |
| スキャン全体 | 109.9秒 | 85.3秒 |
| 通常ファイルの書き込み | 72.9秒 | 57.9秒 |
| うちコミット | 41.9秒 | 40.0秒 |
| 保存用変換のワーカー時間合計 | 1.9秒 | 61.5秒 |
| 統計3列の保存量 | 479.5 MB | 93.3 MB |
| DBファイル | 903.5 MB | 830.8 MB |

同じ旧DBからの各1回。SQLiteは圧縮で空いたページを再利用するため、列の減少量とファイル縮小量は
異なる。全登録パスの譜面情報、統計、警告は展開後に一致した。実際のグラフ取得APIで22,000件を100件
ずつ読み戻した中央値は **546 → 1,214 ms**（前後各10回）。Selectでは背景処理で最大25件ずつ読み込む。
25件ずつSQLと展開を行う補助計測では中央値が未圧縮0.31〜3.21 ms、圧縮0.35〜3.80 msとばらついた。
この補助計測ではアプリ画面への反映時間を測っていない。

空のDBからの初回登録では、基準と案1・2の適用版で **124.3 → 117.6秒**、通常ファイルの書き込みは
**77.7 → 66.6秒**。完成したDBは **862.5 → 337.8 MB**。各1回で、展開後の内容が一致した。

## 2. 同じ内容の書き換えを省く

統計と保存済みペイロードが同じ場合、音量キャッシュの無効化と分析バージョン更新が必要なときだけ
実行する。この経路では主BPMインデックスの更新も省く。スキャン警告は内容と順序が一致すれば
行を維持し、CLIの警告件数には含める。既存の時刻は保持する。

圧縮済みDBから強制再解析し、圧縮のみは **120.6・145.0秒**、書き換え削減を加えると
**111.0・114.6秒**。通常ファイルの書き込みは前者 **56.5・91.2秒**、後者 **58.7・54.8秒**。
途中でビルドや別計測が動いたため、短縮幅のばらつきがある。統計や警告内容と順序は全パスで一致した。
並列処理で変わり得る行IDと実行時刻は比較から除いた。

## 3. WAL自動チェックポイントの閾値

バッチ件数256と `synchronous=NORMAL` を固定し、試作用CLIで閾値のみ変更した。
末尾に `wal_checkpoint(PASSIVE)` を実行し、終了時の残りも含めた。WALサイズは100 ms間隔の観測最大値。
詳細は [SQLiteのWAL仕様](https://www.sqlite.org/wal.html) を参照。

| 閾値 | 10ルートのプロセス時間 | コミット合計 | 末尾チェックポイント | 最大WAL |
| --- | ---: | ---: | ---: | ---: |
| 1,000ページ | 155.0秒 | 52.2秒 | 48 ms | 8.6 MB |
| 4,000ページ | 134.4秒 | 48.8秒 | 573 ms | 22.8 MB |
| 16,000ページ | 112.7秒 | 33.9秒 | 96 ms | 71.8 MB |

単独試行は実行順と並行タスクの影響を含む。INSANEの試行では読み取り専用接続から25件ずつ
50 ms間隔でグラフ列を取得し、同時読み込み中の差も確認した。

| 閾値 | 同時読み込み時のプロセス時間（各2回） | 読み込み p95 | 読み込み p99 | 最大WAL |
| --- | ---: | ---: | ---: | ---: |
| 1,000ページ | 50.6・51.7秒 | 26.6〜42.1 ms | 45.6〜71.4 ms | 13.0 MB |
| 4,000ページ | 53.7・67.0秒 | 32.8〜47.5 ms | 63.5〜102.5 ms | 24.9 MB |
| 16,000ページ | 65.4・56.3秒 | 5.9〜6.5 ms | 151.1〜171.0 ms | 70.4 MB |

読み取りエラーは全試行で0件。4,000・16,000ページではWALが増え、同時読み込み条件で総時間の短縮を
再現できなかったため、製品の閾値は変更しなかった。10ルートの各DBは論理比較で一致した。

## 検証

Windowsでfmt、bmz-playerのcheck、全ターゲットClippy、直列テストが通過した。libは3,205件通過、
87件ignore。WAL閾値を変えた3つのDBで `PRAGMA quick_check` は `ok`。実アプリのSelect操作と
Everything、macOS/Linuxでの計測は未実施。
