# 選曲画面のフォルダ読み込みとスキン描画の計測

2026-11-24。比較元は `37c236bac`。一覧・集計の変更は `538a7362`。フォルダを開いて一覧が返るまでの時間、ランプ集計、表示スレッド上の処理、描画の時間を個別に計測した。

## 実装

- 表示スレッドがランプ集計の結果を受け取らなかったフレームでは、全行へのキャッシュ再適用を省く。一覧を差し替えたときは同じフォルダの再読み込みでも再適用し、画面外の行にも反映する。
- 曲フォルダの集計は、譜面ハッシュ、LN判定用の列、ノーツ数だけを読む。複数の書庫が並ぶ階層で各書庫の内側を調べる際は、ソート済みの子孫パスから対象範囲を二分探索する。
- 仮想フォルダは有効な曲rootをSQL側で絞る。検索条件と並べ替えに必要なスコア・解析・発見日・更新履歴だけを取得する。一覧とランプ集計は同じ抽出・整列・重複排除・件数制限を使う。組み込みのフォルダ定義は共有し、プロファイルに追加した定義は従来どおり読み直す。
- 選曲一覧は登録元を解決した結果、別のコピーへの差し替えが必要な譜面だけを複製する。スコア照会ではプリペアドステートメントと検索結果のマップを再利用する。
- スキンの描画先ごとに不変な画像・数値の参照先と静的画像の判定を保存する。選曲バーの文字描画では、同じフレームの各行に共通する候補を一度だけ用意する。Luaコールバックの評価、動画、アニメーションの進行は従来と同じ。

## 計測条件

Windows、Core i9-12900K、GeForce RTX 5090（ドライバー 621.01）、releaseビルド。変更前後で同じDB・プロファイル・素材を使い、各組の実行順を交互にした。計測用コピーと生ログはローカルの `.local/select-perf/` に置いた。

- **一覧とランプ**。SQLiteのbackupで作成した127,617譜面・12,958フォルダのライブラリと、スコア履歴14,448件を使用。各ビルドを3プロセスずつ起動し、各操作の中央値を取った。一覧の時間にはworker内のDB接続・整列・譜面コピーの解決を含む。表示スレッドへの受け渡し、キー入力から画面に出るまでの時間は含まない。
- **描画**。25譜面の別のライブラリで起動し、DX12実ウィンドウ、1280×720、VSync無効、FPS上限なしで選曲ルートに静止。難易度表はキャッシュ済みの26件を有効にした。スキンごとに各ビルドを3回、各2,400フレーム実行。後半の120フレーム単位のログから、最初と最後の時刻差に対する1,080フレームの描画FPSを計算し、3回の中央値を取った。モニターの実表示回数や入力遅延は計測していない。
- **スクロール**。`scene_plan_profile` の固定スナップショットでカーソルを動かした。各試行で300フレームのウォームアップ後、1,000フレームのCPU描画計画作成時間を測った。GPU投入やpresentを含まない。
- **描画内容**。性能計測とは別に、スクロール開始から390フレーム分の描画プリミティブを順序込みでハッシュ比較した。時計を表示するスキンがあるため、比較専用ビルドの時計ref 21–26を固定した。ModernChicの2種は同じビルド同士でも加算合成画像の色が変わるため、検証用コピーでLuaの乱数seedも固定した。配布用コードと性能計測にはどちらの固定も含まない。

## 一覧と集計の結果

単位はms。部分rootでは3,356譜面を持つ曲rootと同梱サンプルを有効にした。広域rootでは127,599譜面を持つ親rootと同じサンプルを有効にした。全試行で、表示行の内容と並び順のハッシュ、各ランプ・スコアランクの件数が一致した。

| 操作 | 部分root 変更前 → 変更後 | 広域root 変更前 → 変更後 |
|---|---:|---:|
| 通常フォルダを開く（8行） | 3.92 → 3.76 | 3.81 → 4.34 |
| 親のルート一覧に戻る（40行） | 5.30 → 4.17 | 5.51 → 8.66 |
| 譜面一覧を開く（部分229行、広域68,859行） | 16.44 → 14.93 | 4,454 → 3,938 |
| 仮想フォルダ 7K LEVEL 12 を開く（部分416行、広域11,488行） | 1,038 → 69 | 2,972 → 2,077 |
| 通常フォルダのランプ集計（両条件で同一の曲root） | 37.41 → 18.41 | 40.46 → 19.21 |
| 譜面一覧のランプ集計（上記の229行／68,859行のフォルダ） | 2.35 → 1.02 | 803 → 359 |
| 7K LEVEL 12 のランプ集計 | 1,027 → 56 | 2,556 → 1,349 |
| MY BEST のランプ集計 | 1,070 → 61 | 2,291 → 1,529 |
| 当日のランプ更新の集計 | 1,328 → 72 | 2,313 → 1,416 |

広域rootで短い開閉だけを再測定した。各プロセスで同じ8行を開き、40行の親一覧へ戻ったところで計測を終了。変更前後を交互に実行し、先頭の1組を除く各20回の中央値は、開く操作が **3.57 → 3.56 ms**、戻る操作が **5.14 → 4.09 ms**。戻る操作の四分位範囲は変更前5.07–5.22 ms、変更後4.02–4.18 ms。3試行で見えた悪化は再現しなかった。

未集計のフォルダ10,000行、可視25行、新しい結果が届かない状態で、表示スレッドのランプ更新を300回呼んだ。1フレーム平均の3試行中央値は部分rootで **2.364 → 0.004 ms**、広域rootで **2.034 → 0.008 ms**。

単一の子ディレクトリに譜面を持つ書庫が5,000件並ぶ合成階層でも比較した。両版の `beatoraja_folder_listing` と書庫名判定をrelease相当で単独実行し、全5,000パスと並び順を照合した。7試行中央値は **53.24 → 4.07 ms**。ここにはDB読み込みと書庫内容の展開は含まない。

## 検証

`cargo fmt --all --check`、`cargo check --workspace --locked`、`cargo clippy --workspace --all-targets --locked -- -D warnings` が成功。`BMZ_REQUIRE_MZ_SELECT=1` で `cargo test --workspace --locked --no-fail-fast` を実行し、6,027件成功、失敗0件、149件ignored。初回のsandbox実行はlocalhost通信制限で更新テストが待機したため終了し、通常のWindows環境で全件を再実行した。無視指定の性能プローブは上記の実測で別途実行した。

## 次の改善候補

- 6万行を超える一覧は、譜面名を先に表示し、リプレイ・難易度表などの付加情報を段階的に埋める余地がある。途中の表示と、スコア順等で選択位置をいつ確定するかが変わる。
- 高速スクロール中は、通過した行のランプ集計やプレビューの開始をカーソル停止後まで遅らせる余地がある。短時間だけ選択した曲やフォルダで、表示と再生のタイミングが変わる。

## 再計測

一覧の計測には、`BMZ_DATA_DIR` 内に計測専用の `config.toml`、`library.db`、および `profiles/bench/` に `profile.toml`、`score.db`、`collection.db` を用意する。DBは整合したコピーを使う。`BMZ_SELECT_BENCH_FOLDER` と `BMZ_SELECT_BENCH_LARGE_FOLDER` にはそのDBに登録されたフォルダパスを指定する。

```console
cargo test --release -p bmz-player --locked --lib profile_select_navigation -- --ignored --nocapture
cargo run --release -p bmz-player --locked --example scene_plan_profile -- select <skin> scroll
cargo run --release -p bmz-player --locked -- --profile bench --smoke-exit-after-frames 2400
```

CPU計測では `BMZ_SCENE_PROFILE_FRAMES=1000` を指定する。実ウィンドウ計測では計測用プロファイルで対象のSelectスキンを選び、`RUST_LOG=warn,bmz_player=info,bmz_player::select_profile=debug` を指定する。フォルダの表示規則は [select-folders.md](../../docs/select-folders.md)、フレーム計測は [frame-pacing.md](../../docs/frame-pacing.md) を参照。
