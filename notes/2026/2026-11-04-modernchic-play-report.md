# ModernChicのPlay画面に関する8項目の報告

実施日: 2026-11-04。対象commit: `93d7bfaf`から。
環境: Windows 11、ModernChic Ver 4.71（一部はOldも）、release / debugビルド。

[暫定対応](2026-11-01-modernchic-compatibility.md)の後、利用者から想定と異なる動作が8項目報告されました。
前回の検証は同梱サンプルのオートプレイが中心で、手動プレイ、BGAのある譜面、実曲の曲名は
確認していませんでした。

## 原因と修正

| 報告 | 原因 | 修正 |
|---|---|---|
| 曲開始時にミュージックバーが変な場所に出る | 未特定（下記） | 未修正 |
| BGA上部の曲名等にフォントが適用されない | 影と難易度色が出ていなかった（下記） | 修正 |
| BPMが読み込まれない | Luaの`draw = false`を常に非表示にしていた | 修正 |
| BGAが読み込まれない | 未特定（下記） | 未修正 |
| CN・スクラッチ等の色がつかない | Play中は単色の密度グラフだった | 修正 |
| シーケンスバーが出ない | 現在位置カーソルが未実装だった | 修正 |
| 詳細情報が全体的に正しくない | 打鍵数の誤り、グラフの未実装、連続プレーの不具合の複合 | 修正 |
| 鍵盤を押すと秒間密度が異常 | timerの再起動の誤検知 | 修正 |
| 連続プレーの算出、ログ | ロード時の曲名が空で、切った曲名も文字化けしていた | 修正（再起動で消える） |

### Luaの`draw`のboolean

`Play/lua/sp/info.lua`の現在BPMは`draw = not CUSTOM.OP.isMainBpm`で、関数の否定なので`false`です。
beatorajaの`LuaSkinLoader.serializeLuaScript`はbooleanをnullとして読み、条件を付けません。
BMZは常に非表示へ変換していたため、BPM固定の譜面では現在BPMが出ず、BPM変化のある譜面でも
主BPMのときしか出ませんでした。過去のスクリーンショットでも空欄です。

### Playのロード時の譜面情報

beatorajaは解析済みの譜面でPlayスキンを読みますが、BMZのロード時状態には譜面長しかありませんでした。

- タイトルの色が難易度色にならず白でした（`COMMONFUNC.setRGB()`）。
- エフェクター枠が欠けていました（`option(NO_LN)` / `option(LN)`）。
- ロード中のアーティストが空でした（`constantText`）。
- `main_state.text(12)`が空文字になり、全曲が同じ曲の連続プレーとして数えられていました。

譜面ワーカーが渡す値を譜面長から`PlaySkinChartFacts`へ広げました。変換後の譜面の値を使うためです。
難易度表のtextはDBが要るのでwindow threadで渡します。

### 文字の影

報告の「タイトル文字」は、開始時の大きな曲名ではなく、プレー中にBGA上部へ順に出る曲名・ジャンル等を
指すことを確認しました。画像フォントは既定の無効です。

`SkinTextFont`と通常の`SkinTextBitmap`は`shadowColor`を読まず、`shadowOffset`があれば文字色の半分の
明るさで影を描きます。ModernChicは`shadowOffsetX = 2`だけを指定するため、BMZでは既定の透明色と
解釈して影が出ていませんでした。影がなく色も白いため、別の書体のように見えていたと判断しました。

手元のスキンの`shadowColor`は透明色（`00000000`）だけです。透明・未指定のときだけbeatorajaに合わせ、
不透明な色の指定は従来どおり使います。`shadowColor`を読む距離フィールドのフォントは対象外です。

### timerの再起動の誤検知

Luaへ返す開始時刻は「画面時刻 − 経過ms」の逆算で、2 msを超える変化を再起動としていました。

- 入力オフセットが正だと`input.time`が譜面時刻より先になり、経過が0に丸められます。その間は開始時刻が
  フレームごとに進み、1打鍵が複数回に数えられます。
- 画面時刻とsnapshotの差は環境に依存します。`park_timeout`の精度を上げる処理はありません。

打鍵・判定・ボム・HOLD・HCNのtimerは、経過時間が2 msを超えて減ったときだけ再起動とします。
当初は全timerへ適用する計画でしたが、`timer_elapsed(41)`のテストで、TIMER_PLAYのように再生速度で
開始時刻が動くtimerを壊すと分かり、対象を絞りました。RHYTHMも同じ理由で従来どおりです。

### スキンファイルのバイト保持

ModernChicは`string.sub(title, 1, 32)`を連続プレーの判定キーにします。日本語の曲名は文字の途中で切れ、
`to_string_lossy`で置換されるため、読み戻すと一致しませんでした。保存をバイト列に変えました。

保存先はメモリのままで、再起動すると連続プレーや累計は消えます。判断は依頼者に確認しました。

### Play中のノート分布

- ノート種別の集計を`chart_graph`へ移し、Resultと共有します。あわせて`long_notes`の線形探索をなくしました。
- 判定とFAST/SLOWはgameplay threadで判定イベントから増分更新し、最短750 ms間隔で公開します。
  動画出力は再現性のため、壁時計ではなく画面時刻で同じ更新をします。
- `delay`の既定値を`JsonSkin.JudgeGraph`と同じ500 msにしました。Resultと選曲の表示にも影響します。
- Practiceの開始・終了カーソルは実装しませんでした。計画には含めていましたが、beatorajaはこれらを
  Practiceの設定中だけ描き、BMZでは練習パネルが同じ役割を持つためです。

## 検証

自動テスト: 追加は`bmz-skin`（`draw`のboolean、timerの判定、バイト保持、実スキンでの連続プレー）、
`bmz-player`（ロード時の譜面情報、判定の増分更新）、`bmz-render`（色、カーソル、`delay`、影）です。

実スキン（ModernChic 4.71、動画出力）: 日本語の曲名、BPM変化、スクラッチ、LN、BGAを含む7鍵の
テスト譜面で、次の表示を画像で確認しました。

- BGA上部の曲名が難易度色で影付きになり、現在BPM、エフェクター枠、ロード中のアーティストが出ます。
- ノート分布は種別の色と判定の色が出て、シーケンスバーが動きます。
- 詳細モードのレーン別打鍵数の合計がコンボ数と一致しました（104）。
- READYと譜面開始の前後を1フレームずつ見ても、ミュージックバーの位置ずれはありません。

連続プレーは`modern_chic_consecutive_play_log_follows_the_chart_when_available`で、実際のModernChicの
Luaを動かして確認しました。同じ曲で回数とログが増え、別の曲でリセットされます。

インストール済みLuaスキンの互換比較: 回帰0件です。差分はModernChicのplay5 / play7の現在BPMの
destinationだけで、SocialSkinの差分はベースライン間でも揺れる乱数です。

Play描画準備のCPU時間（`play_plan_profile`、release、471 play7、レーンあたり8ノーツ、3000フレーム、2回）:

| 条件 | 平均 | p95 |
|---|---|---|
| グラフなし | 117.7 / 120.9 µs | 164 / 181 µs |
| 180秒分のグラフ | 125.4 / 120.0 µs | 188 / 175 µs |

差は実行ごとの揺れと同程度です。GPU・present・実FPSは測っていません。

## 未確認事項・残課題

- 曲開始時のミュージックバー: 動画出力では再現せず、原因は未特定です。実際のウィンドウでは
  `--smoke-exit-after-play-frames`の範囲で開始数秒より先を撮れず、曲開始の瞬間は確認していません。
  今回の変更で解消した可能性はありますが、確認できていません。報告者の画面の録画が必要です。
- BGA: テスト譜面の画像BGAは表示されました。動画BGAと、症状が出た譜面は未確認です。報告者に譜面名の
  確認が必要です。
- 手動プレイの実機確認は未実施です。KEYONの誤検知はテストで確認しました。
- beatorajaとの同条件比較、Old版の画面、5/10/14鍵、Windows以外のOSは未確認です。
- number 92（主BPM）は最初のBPMで、beatorajaの最も多いBPMとは異なります。今回は変更していません。
- 距離場フォント（`font.type`が1 / 2）の描画は未対応です。報告の件とは無関係でした。
