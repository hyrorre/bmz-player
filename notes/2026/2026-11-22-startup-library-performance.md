# 起動とライブラリ再スキャンの計測

Windows 11（build 26300）、Core i9-12900K、release ビルドで検証した。
ライブラリの SQLite バックアップからビルドごとに専用 DB を作った。
登録ファイルは127,720件、登録済み書庫は834件、文書フラグの未確定行は0件。
DX12、1280×720、ウィンドウ表示、WASAPI共有、起動時の自動再スキャン無効で固定した。
同梱スキンと、mz-select / ECFN Decide / WMII_FHD Result の組み合わせを別々に測った。

計測はビルドの実行順を往復させ、各7回のうち初回を除く6回の中央値を採った。
毎回新しいプロセスを起動し、実ウィンドウで10フレーム描画後に終了した。
初回表示は[起動診断](../../docs/startup-diagnostics.md)の
`startup_to_first_present_ms`。生ログと専用DBは作業環境の `.local/startup-scan-perf/` に置いた。

## 文書フラグの補完

起動時とスキャンワーカーの起動時に、文書の有無が未確定のフォルダーを検索する。
従来は補完済みでも通常のフォルダー索引を走査した。
library schema 40 で未確定行のフォルダーだけを収める部分索引を追加した。
既存の譜面データはそのまま使える。移行時に1回、索引作成のため全行を読む。

| 条件 | 変更前（a75579c5e） | 部分索引あり |
|---|---:|---:|
| 同梱スキン・ライブラリ移行と補完 | 159 ms | 12 ms |
| 同梱スキン・初回表示 | 902 ms | 770 ms |
| カスタムスキン・ライブラリ移行と補完 | 159 ms | 12 ms |
| カスタムスキン・初回表示 | 1,158 ms | 1,025 ms |

## Windows 8.1 互換対応の前後

PR #137 の直前 `c83f0aa77` と取り込み直後 `3a98b21f2` を release でビルドした。
各 exe の `--version` でコミットを照合した。共用 target の初回ビルドで識別子が以前の
コミットを示した通常ターゲット版は除き、空の専用 target で再ビルドして比較した。
MSVC、FFmpeg DLL、DX12、DBとスキンは共通。同じWindows 11で次の値になった。

| ソースと Rust ターゲット | 同梱・初回表示 | カスタム・初回表示 | プロセス開始から初回表示ログ（同梱 / カスタム） |
|---|---:|---:|---:|
| 対応前・stable pc-msvc | 952 ms | 1,177.5 ms | 970 / 1,193.5 ms |
| 対応後・stable pc-msvc | 926 ms | 1,183.5 ms | 943 / 1,201 ms |
| 対応後・nightly pc-msvc | 924.5 ms | 1,155 ms | 941.5 / 1,171.5 ms |
| 対応後・nightly win7-msvc | 920.5 ms | 1,169.5 ms | 939 / 1,186 ms |

同じstableターゲットで比較した対応前後の差は同梱で −26 ms、カスタムで +6 ms。
同じ対応後ソース・nightlyでターゲットを変えた差も同梱で −4 ms、カスタムで +14.5 ms
と方向が分かれた。各6回の分布は重なり、このPCで一貫した起動の悪化は確認できなかった。
nightly は `nightly-2026-11-19` と `-Z build-std=std,panic_abort`。
Windows 8.1 実機および配布物の SxS DLL 配置での起動時間は未計測。
当時のプレイ中の結果は[互換対応の記録](2026-11-19-windows-81-compat.md)にある。
