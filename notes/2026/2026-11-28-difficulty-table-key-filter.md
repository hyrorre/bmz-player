# 難易度表の未所持譜面とキーモードフィルター

ローカルの`main`（`13e535b9`）で実装しました。作業開始時のGitHubの`main`は`835bf446`で、ローカルの`main`に含まれています。

beatorajaの両コミットで、`DifficultyTableAccessor`がエントリとヘッダーの順にmodeを解決し、両方が不明なら`0`を使うことを確認しました。`ModeFilter.matches()`は`0`を通し、`BarManager`は一覧全体が消える場合に次のフィルターを試します。`SongBar`は所持譜面が見つかると、その譜面の`SongData`に表の情報を補います。[0.8.9 `83574048`](https://github.com/exch-bms2/beatoraja/tree/83574048ba489082eb46df7fe9806b464bf1f526) / [master `a77ebc20`](https://github.com/exch-bms2/beatoraja/tree/a77ebc20b794d45115a420edaeabf5b6d08d3a91)

同梱の`jbms-parser`で定義されているmode hintは大文字・小文字も含めて完全一致です。BMZは有効なhintを選曲用の表記に変換して保存します。上流のフィルター上で同じIDを持つ`popn-5k`と`popn-9k`はどちらも`9K`になり、24K・48Kも既知の値として保持します。非文字列のJSON値は無効としてヘッダーへのフォールバックを続けます。

SQLiteのライブラリmigration 41は、既存の表エントリにNULLのmodeを追加します。メタデータの記録をバージョン2に更新し、有効な表を起動後の再取得対象にします。再取得時の表・譜面・コースを同一トランザクションで書き込むため、保存失敗時も以前の表が残ります。

選曲リストの表示とキーモードの自動送りは同じ判定を使います。譜面取得後も一覧を1度だけ絞り込み、コース構成譜面は保存順で表示します。

現在の仕様は[キー操作](../../docs/controls.md#キーモードフィルター)と[難易度表の設定](../../docs/settings.md#難易度表)を参照してください。

## 検証

macOS arm64 / Rust 1.100.0で、fmt、`bmz-player`のcheck、全ターゲットClippy、crateの全テストを実行しました。ローカルHTTPポートを使える環境での全テストは3,515件成功、失敗0件、70件ignoreでした。

ローカルHTTPの難易度表を取得してSQLiteへ保存し、実際の選曲一覧を読み直しました。複数`data_url`と`data_rule`経由のmode、取得・保存失敗時のキャッシュ、譜面登録と曲rootの切り替え、コースの表示順、配布元URL、ランダム選曲候補を自動テストで確認しました。GUIでのF5操作と、素材不足でスキップされた外部スキンの動作確認は未実施です。
