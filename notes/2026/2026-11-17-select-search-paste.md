# 選曲の検索欄への貼り付けとCtrlのスクロール（#117）

選曲の検索欄では、egui-winit が生成した貼り付けイベントが検索の編集処理に届かず、Windows で Ctrl+V を押すと曲名の代わりに `v` が入力されていました。

検索モード中は、BMZ メニューが受け取らなかった貼り付けイベントを現在のカーソル位置に反映します。改行とタブは空白に変換します。空のテキストや読み取り失敗では検索語を保ち、IME の変換中は変換を優先します。

スクラッチを押したまま検索モードへ入ると、選曲画面が長押しによる移動を続ける経路がありました。検索モードに入るときに開始済みの長押し移動を解除します。

Windows の同梱 Select スキンとサンプル曲で、修正前の入力を再現し、修正版で Ctrl+V から Enter で検索結果を表示するまでを確認しました。左 Ctrl が通常の選曲では Scratch Down として行を移動し、検索中は Ctrl 単体と Ctrl+V のどちらでも選択行が動かないことを確認しました。検索中に BMZ メニューでテキスト欄へフォーカスを移した場合は、貼り付けがその欄に入ることも確認しました。

日本語の途中挿入、複数行、空の入力、IME 変換中、別キーの貼り付けイベントとの区別をテストに追加しました。検索開始前から左 Ctrl を保持したケースは、Windows の個別テストで確認しました。macOS と Linux の実画面での操作は未確認です。

整形、`bmz-player` の型検査と全ターゲットの Clippy、および通常テスト（3,288 件成功）が通りました。

その後のレビューで、貼り付けで検索語が256文字を超えないように切り詰めるようにしました。
