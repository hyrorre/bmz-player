# Luxez-Flat詳細オプションの角と継ぎ目

本体の基点: `main` / `e244d8c4`。Luxez-Flatの基点: `main` / `196a6ad`。
[前回の見た目調整](2026-10-20-detail-option-style-fixes.md)に対する追加の指摘を調べた。
開始時の本体とスキンに未コミットの差分はなかった。
作業中にmz-selectの余白調整`a7c3713c`が追加されたため、その変更を保持して検証した。

## 原因と修正

- ボタンの四隅: 同じカードから背景色込みで切り出す方法自体は維持した。本体の画像描画が
  最近傍表示でもUVを半画素ずつ縮めていたため、2倍表示では元の画素の幅が不均等になり、
  異なる範囲を切り出したボタンと背面で発光の参照位置がずれていた。
  最近傍表示は元のpixel境界を使い、線形補間だけに半画素の保護を残した。回転画像も同じ処理を通す。
- 項目枠の上角: 見出しの色変化を含む133pxの縦枠を502pxへ伸ばしていた。
  見出し側の22pxは等倍で描き、本体側の平坦な1行だけを480pxへ伸ばす。
- 項目枠の下角: 角の内側へ直線部分の発光を流用していた。
  上角・下角とも、輪郭と同じ元画像の行から内側まで切り出し、24pxの範囲をそのままつなぐ。
- 既存PNG、設定値、入力、クリック範囲、開閉アニメーションは変更していない。

現在の契約は[詳細オプション](../../docs/select-detail-options.md#luxez-flat)と
[画像の拡大縮小](../../docs/skin.md#画像の拡大縮小)へ反映する。

## 検証

- 小さなGPU回帰テストで、分割画像と一枚の画像を1倍・2倍・3倍で描き、元の画素列および
  分割前後の一致を確認する。回転0のRotatedImage経路も含む。修正前は2倍表示で失敗した。
- Luxezの実素材を使うGPU回帰で、シアン・緑・橙・紫・赤の5色を1920×1080と3840×2160で描画し、
  ボタンの角の背景色が同じ横位置の本体色と一致すること、四隅の有色画素が元カードと一致することを確認した。
- プレビューの保存先は、テストに`BMZ_SKIN_PREVIEW_DIR`を指定した場合だけ保持する。
  未指定時は従来どおりテスト終了時に一時ディレクトリを削除する。
  今回の画像は`.local/performance/2026-10-20-luxez-corners/after/`へ出力する。
- `cargo fmt --check`、`cargo check --workspace --locked`、
  `cargo clippy --workspace --all-targets --locked -- -D warnings`が成功。
- 制限下の全体テストでは保存・リンク作成等が失敗した。代表例の
  `storage::replay::tests::save_and_load_replay_file`は、制限下で`os error 5`、
  同じバイナリを通常のWindows権限で実行すると成功した。
  制限下の全体実行は中断し、通常のWindows権限で`cargo test --workspace --locked --no-fail-fast`を再実行して全成功。
  制限下の記録は`workspace-tests.log`、成功した全体検証は`workspace-tests-native.log`に保持した。
- 6解像度（1920×1080、3840×2160、1280×720、960×540、1024×768、2560×1080）のGPU previewを生成した。
  1920×1080・3840×2160で角とボタン、1280×720・960×540で縮小時の表示を目視した。
- 通常ウィンドウでの操作、macOS / Linuxでの表示は未実施。

## 追補: LN MODEの背景と隣接候補への発光

本体の基点: `473fcdf5`、Luxez-Flatの基点: `5930317`。
ユーザーの追加画像で、LN MODE見出しの横線・右側の括弧と、未選択ボタンの角に残る色差を確認した。
前回のプレビューでも見えていたLN MODEの文字混入を見落としていた。

- 橙のGASカードは焼き込み文字が左右の発光部分にまで達していた。
  見出し内側の22pxだけ、同じ橙のLANE STYLEカードの文字がない部分へ切り替えた。
  四隅・縁・本体・ボタンはGASの素材をそのまま使う。
- ボタンの角には正しい背景色があったが、候補ごとにボタン→選択素材を描いていたため、
  次のボタンの不透明な角が、先に描いた19pxの発光を矩形で消していた。
  列内を全ボタン→全選択素材→全文字の順へ揃えた。通常パネルの素材とカーソルの重ね方に合わせている。
- 実画素でも、下のONの左上に対応するカーソル素材はRGBA `(254,183,50,50)`なのに、
  修正前の描画結果は`(0,88,94,255)`のままで発光が消えていた。
  修正後は`(50,107,85,255)`となり、素材のalphaどおりに発光が重なった。
- 前回の画素比較は四隅24pxと発光のない数値欄だけだったため、見出し中央と隣の候補へ届く発光を検出できなかった。
  今回は見出しの色相・連続性、全候補の描画順、隣接候補の角への発光を回帰の対象に追加した。

追補のGPU検証は3件成功（四隅・隣接候補の発光・プレビュー）。通常のLuxez回帰は9件成功。
6解像度の84画像を`.local/performance/2026-10-20-luxez-corners/header-glow/`へ保存し、
1920×1080と3840×2160でLN MODEの見出しとボタンの角を目視した。
描画順の回帰は修正前のスキンで失敗することも確認した。
`cargo fmt --check`、`cargo check -p bmz-player --locked`、
`cargo clippy -p bmz-player --all-targets --locked -- -D warnings`が成功。
通常のWindows権限で`cargo test -p bmz-player --locked`を実行し、2,581成功・37 ignored。
全体ログは`followup-player-tests.log`、GPUログは`followup-gpu.log`に保持した。
通常ウィンドウでの実操作、macOS / Linuxでの表示は未確認。
