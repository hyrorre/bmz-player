# EXTRA NOTEの配置仕様

Kaleidのダミー各種とポーションは、EXTRA NOTE有効時に配置前に除去します。
表示専用ノーツの除去だけではアシストへ昇格しません。実地雷を維持する本書の規則は
通常譜面・Kaleid譜面とも同じです。HLNとフリーゾーンは保持区間を予約し、
その内部へEXTRA NOTEを追加しません。

EXTRA NOTEはBGMイベントを、音と時刻を保って通常ノーツへ移します。
BMZ独自の配置仕様です。LR2の音別レーン傾向と、LR2oraja ED-rianの前後間隔の
検査を参考にし、LN・地雷を保ったまま追加数と演奏負荷を制限します。

## 適用順と設定

通常はLN policy、SCROLL / LONGNOTE / MINE、鍵盤数変換、DOUBLE、レーン配置を確定した後に
適用し、その後でAUTO SCRATCHの実効判定を行います。
DP OPTIONの`BATTLE` / `BATTLE AS`は、SPへのEXTRA NOTE追加、両側への複製、左右の配置設定の順です。
追加元のBGM選択・ノーツは左右共通になり、1P / 2Pの配置設定は複製後にそれぞれ適用します。
G-BATTLEの追加対象はプレイヤー側です。相手の採点用譜面・表示用ノーツには追加しません。

- `EXTRA NOTE DEPTH=0`は無効です。
- 正のDEPTHは同じ実時刻に追加するノーツ数の上限です。tickが異なっても実時刻が同じなら合算します。
  BATTLE系では複製前のSPに対する上限で、採用した追加ノーツを左右へ複製します。
- DEPTHを増やしても以下の制限は緩和しません。
- スクラッチへの追加は`EXTRA NOTE SCRATCH=ON`の場合に限ります。
- `EXTRA NOTE TYPE`は予約値で、配置には使用しません。

## 音とレーンの対応

追加時点の元ノーツ（通常ノーツ・LN始点と重ねたキー音）から、音ごとのレーン使用数を集計します。
同じ音源パスとスライス開始・長さを参照するSoundIdは同一の音として扱います。
パスは区切りと`.` / `..`を字句的に正規化し、大文字小文字は区別します。ファイルは読みません。

最多使用レーンを基本レーンとします。未使用音や同数の候補は、同一音の代表SoundIdと
スライス範囲による固定ハッシュで決めます。インストール先パスや配置用乱数には依存しません。
安全条件を満たす候補の優先順は、同じ音の使用実績、基本レーンからの距離、前後の空き時間、
直近2秒の追加数の少なさ、固定順です。基本レーンが使えない場合も元ノーツは移動させません。

同時刻のBGMは、元ノーツに使われた音、BGMでの反復数、固定ハッシュ、SoundId、tickの順に
調べます。置けないイベントを飛ばして、残りも調べます。

## 前後間隔と衝突回避

譜面時刻のマイクロ秒で判定します。各ノーツ位置のBPMから次の最小間隔を計算します。

| レーン | 最小間隔 |
| --- | --- |
| 鍵盤 | `max(125ms, 30000ms / BPM)` |
| スクラッチ | `max(250ms, 30000ms / BPM)` |

小数マイクロ秒は切り上げます。前後両方の位置で計算した最小間隔の大きい方を要求します。
境界と等しい間隔は許可します。遠い低BPMノーツの禁止範囲も検査します。
追加済みノーツも後続の検査対象です。候補不足でも間隔を緩和しません。
DP OPTIONのBATTLE系ではこの検査を複製前のSPに適用します。
後段でS-RANDOM等を指定した場合、追加ノーツもその配置変更の対象になります。

BPMはその位置の値の絶対値とし、SCROLL / SPEEDは使いません。不正値は直前の有効値を
引き継ぎ、初期値も不正なら120とします。BPM / STOPイベントの実時刻は変えません。

LN / CN / HCNの始点・終点の前後間隔と保持区間を予約します。
地雷・不可視ノーツも除去せず、同レーンの前後間隔を検査します。
MINE REMOVE等を明示的に併用した場合は、その変換後の譜面を基準にします。

## 同時押しと局所密度

片側のスクラッチ以外の鍵盤数をKとし、追加時の「同時打鍵レーン＋保持中LNレーン＋
同時スクラッチレーン」を最大`ceil(K/2)`に制限します。既存譜面が上限以上なら追加しません。
同じレーンのLN始点と保持は二重に数えません。通常のDPは左右独立です。

候補時刻tについて、元ノーツの通常ノーツとLN始点を`[t-1秒, t+1秒)`で数えた値をNとします。
追加後の`(t-1秒, t]`の追加数が`min(8, ceil(N/2))`以下の場合に限り許可します。
Nが0なら追加しません。追加ノーツはNに含めず、通常のDPは左右別々に判定します。
片側で毎秒8追加ノーツを上限とし、元譜面の低密度区間ではさらに制限します。

候補は元の最初の演奏ノーツから最後の演奏ノーツ／LN終端までです。
採用したBGMイベントだけを元のSoundId・tick・実時刻のまま1個の通常ノーツへ移します。
追加できない音はBGMに残し、無音ノーツは生成しません。

## 保存と検証

実際に1個以上追加されたときだけ実効Assistとします。ランプ・回数等はclear-only保存し、
数値ベスト・履歴・リプレイ・IRを更新しません。追加ゼロならEXTRA NOTEをOFFにしたときと
同じ保存判定です。他の実効アシストがあれば、その判定が優先します。
無効だったEXTRA NOTEのbitは保存用assist maskから除外し、履歴のIR再送でも同じ扱いにします。
詳細は[スコア保存条件](score-persistence.md)を参照してください。

回帰テストでは音イベントの保存、既存オブジェクトとLN・地雷の保持、BPMと時間境界、
同時押し・局所密度・DP・対戦表示・配置オプションとの併用、実効有無による保存とIRを確認します。
