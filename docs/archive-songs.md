# 書庫内譜面の直接再生

ZIP / RAR / 7zを曲rootへ置くと、スキャンで内部のBMS / BME / BML / PMS / BMSONを個別に登録します。
選曲・Autoplay・Practice・コース・リプレイで通常の譜面と同じように選べます。
スキャン時は譜面bytesを解析し、曲フォルダ全体の事前展開は不要です。
solid書庫では他の資源も順に復号しますが、スキャン用に保持しません。
登録・更新・同一譜面コピーの選択は[曲の取得元とスキャン](song-sources.md)を参照してください。

```powershell
bmz-player songs load "G:/BMS/OTHERS"
bmz-player "G:/BMS/OTHERS/set.zip!/song/chart.bms" -a
bmz-player -P "G:/BMS/OTHERS/set.rar!/song/chart.pms"
bmz-player export video "G:/BMS/OTHERS/set.7z!/song/chart.bmson" -o out.mp4
```

`!/`より前が元書庫、後ろが内部譜面です。相対指定では書庫部分だけを現在の作業ディレクトリから
絶対パスへ解決します。書庫名だけを再生コマンドへ渡した場合は、スキャンして選曲する案内を表示します。
全体同期後も保持する曲rootは`songs add`で登録してください。

## 選曲画面のフォルダ構成

選曲画面では、書庫を拡張子と`!`を除いた名前（`pack.zip`なら`pack`）のフォルダとして、
通常のフォルダと同じ規則で並べます。
譜面だけを含む末端のフォルダは親の一覧へ譜面を直接並べ、さらに下にフォルダがあるときだけフォルダとして表示します。

書庫の直下に譜面が無く、フォルダが1つだけ入っている場合は、書庫の段を省き、
中のフォルダを書庫の位置に置いたものとして表示します。
書庫を展開して中身のフォルダを曲rootへ置いたときと同じ見え方です。

| 書庫の中身 | 表示 |
|---|---|
| `pack.zip` → `chart.bms` | 譜面を親の一覧へ直接並べる |
| `pack.zip` → `song/chart.bms` | 同上（書庫の段を省く） |
| `pack.zip` → `Pack/song1/…`, `Pack/song2/…` | `Pack`フォルダ。中に入ると各曲の譜面を並べる |
| `pack.zip` → `song1/…`, `song2/…` | `pack`フォルダ |
| `pack.zip` → `chart.bms`, `song/…` | `pack`フォルダ |

省くのは書庫の段だけで、名前の変更も表示だけです。DBの譜面パスや曲rootの判定は変わりません。

## 資源と保存先

ライブラリDBとViewer IPCには元書庫と内部エントリ名を保持します。

再生（Autoplay・Practice・コース・リプレイ・Viewer・動画出力を含む）と生成試聴は、書庫を
ディスクへ展開しません。beatorajaの`SongResource`と同じく、音源・BGA・動画・STAGEFILE等は
`pack.zip!/song/kick.wav`のような書庫内パスのまま扱い、workerが譜面の使う資源をメモリへ読み込みます。
音声と動画もFFmpegへメモリ上のバイト列を渡してデコードします。

- 読み込むのは譜面が参照する資源だけです。音源は拡張子補完の候補（beatorajaの順）をすべて含み、
  BGAは同名の別拡張子への置き換え後、STAGEFILE / BACKBMP / BANNERは同名画像の補完後のファイルです。
- ZIPと非solidのRARは対象のエントリだけを直接読みます。solidのRAR / 7zはエントリを途中から読めないため、
  譜面フォルダの資源を1回の順読みでまとめて読み、使わなかったものは破棄します。
  必要なエントリを読み終えた時点で読み取りを止め、7zでは対象の無いブロックを復号しません。
  複数曲を1つにまとめたsolidのパックでは、曲ごとの初回読み込みでブロックの大半を復号するため、
  1曲あたり数秒〜十数秒かかることがあります。計測は
  [作業記録](../notes/2026/2026-10-25-archive-direct-playback.md)を参照してください。
- 書庫内の名前は完全一致を優先し、無ければ大文字小文字を区別せずに探します。
  展開先がWindowsのファイルシステムだった以前の動作と同じく、`KICK.WAV`の指定で`kick.wav`を読めます。
- 読み込んだ資源はプレイ中保持し、動画BGAの開始時やリトライでも書庫を読み直しません。
  プレイ終了後も直近3書庫まで（合計1GiBまで、最新の書庫は超えても保持）を再利用します。
  資源の追加読み込み後にも合計容量を再確認し、古い書庫のキャッシュ参照を外します。
  再生・ロード中の所有者が保持している資源は、その所有者が解放するまで残ります。
  同じ書庫の別譜面へ移るとき、保持量が1GiBを超えていれば次の譜面が使わない資源を破棄します。
  同じ資源セットを別の再生・試聴・ロードが使っている間は破棄しません。
- 選曲位置が試聴の開始待ち時間を過ぎて安定すると、solid書庫の譜面フォルダを
  低優先度workerで先読みします。1件ずつ実行し、選択変更時は古い要求をキャンセルします。
  宣言されたフォルダ内資源が256MiBを超える場合と非solid書庫は事前読み込みを省略します。
  Playが同じ書庫を要求すると進行中の読み込みを待って再利用し、同じブロックを重複して復号しません。
  先読みした未使用資源は、実際の譜面が使う資源を確定したときに通常どおり破棄します。
- 読み込み後に書庫が更新された場合も、プレイ中の資源は読み込んだ世代のまま使います。
  次のロードで書庫を再確認し、新しい世代を読み込みます。
  読み取り用の内部パスには資源セットのIDを付け、音声・画像・動画のデコーダーまで渡します。
  動画の遅延開始や開き直し、古いロードの遅延完了でも、別セットへ読み替えません。
  内部パスはプロセス内だけで使い、DB・スコア・リプレイ・Viewer IPCには従来の識別子を保存します。

選曲画面の画像と明示試聴、曲テキストを開く操作は、外部のデコーダーやアプリにファイルを渡すため、
対象エントリだけを`AppPaths.cache_dir/song-archive-assets`へ取り出します。書庫全体は展開しません。
この取り出しは同時に2件までに制限します。
`BMZ_CACHE_DIR`を設定した場合もその配下を使い、スコアやリプレイに一時展開パスを保存しません。
譜面のMD5 / SHA-256は内部譜面bytesから計算するため、通常フォルダにある同じ譜面と記録を共有できます。
同じ譜面bytesを含む別書庫でも、音源・画像・動画BGAは選択したコピーの資源を使います。

音源、BGA、STAGEFILE、BACKBMP、BANNER、PREVIEWは譜面のフォルダを基準に解決します。
`../shared/key.wav`のような書庫内の共有資源は利用できます。書庫外へ出る参照はエラーです。
画像・音声の拡張子補完と、PREVIEW未定義時の`preview*.wav` / `.ogg`等の探索も行います。
明示試聴が見つからなければ、譜面から試聴音声を生成します。

読み込んだ資源と取り出したファイルは、書庫内容のSHA-256で世代を分けます。資源だけの更新も
ファイル情報の変化から検出し、選曲画像・明示試聴・生成試聴と次のプレイへ反映します。
再生中の世代は置き換えません。
計算したSHA-256は、サイズ・更新日時・作成日時（Unixではinodeとctimeも）と組にして
ライブラリDBの`song_archive_fingerprints`に記録します。これらが一致する間は書庫全体を読み直さず、
Play開始時の確認もscan時の世代と一致すれば書庫全体を読み直しません。
読み込み中に書庫のファイル情報が変われば、その読み込みをエラーにします。
リトライは再ロードしますが、書庫が変わっていなければメモリ上の資源を再利用します。
Practiceの反復中はロード済み資源を維持します。
Practiceへ再入場、またはViewerのF5再読込で更新を反映できます。
世代情報のない音量解析DBキャッシュは書庫再生へ流用しません。

`song-archive-assets`は書庫ごとに現在の世代だけを残し、古い世代は次の取り出し時に削除します。
サイズが合わないファイルは取り出し直し、キャッシュ内のリンクは拒否します。
以前のバージョンが書庫全体を展開した`song-archives`は使わなくなりました。プレイ停止中に削除できます。

F3は元書庫をファイルブラウザーで選択します。曲テキストを開く操作（既定は`9` / `Numpad9`）は、
同じ内部曲フォルダにある`.txt`をバックグラウンドで展開して開きます。

## 対応範囲と制限

ZIPはStore / DeflateとZIP64に対応します。RARは`rars 0.10.0`、7zは`sevenz-rust2`の
既定codecを使用し、外部の展開実行ファイルは不要です。通常のsolid RAR / 7zも対象です。
暗号化、分割書庫、自己解凍形式（SFX）、7zのanti-item、リンク・特殊ファイルには対応しません。
絶対パス、書庫外への`..`、危険な名前、重複エントリ、大小文字やUnicode NFC正規化で衝突する名前は拒否します。
書庫内の書庫をさらに曲rootとしてスキャンする処理は行いません。

Unicode指定がないファイル名はUTF-8を優先し、次にCP932で読みます。
CP932の日本語に含まれる`0x5c`を区切り文字と誤認しないよう、文字列へ復号してから区切りを正規化します。

既定の読み取り上限は次のとおりです。

| 対象 | 上限 |
|---|---:|
| 書庫ファイル | 8 GiB |
| 展開後の合計 | 16 GiB |
| 1ファイル | 4 GiB |
| 1譜面 | 64 MiB |
| ヘッダー | 64 MiB |
| エントリ数 | 100,000 |
| 辞書 | 256 MiB |
| RAR reader作業領域 | 512 MiB |

辞書・reader作業領域は全方式の合計メモリ上限ではありません。RARでは利用ライブラリのresource policyへ
辞書・作業領域上限を渡し、7z本文ではLZMA / LZMA2 / PPMdのpropertiesを事前確認します。
7zの圧縮ヘッダー処理については、利用ライブラリの公開API上、
展開時メモリ使用量の厳密な上限までは保証できません。
