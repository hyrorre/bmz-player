# 書庫内譜面の直接再生

ZIP / RAR / 7z を曲rootへ置くと、スキャンで内部の BMS / BME / BML / PMS / BMSON を個別に登録します。
選曲・Autoplay・Practice・コース・リプレイで通常の譜面と同じように選べます。
スキャン時は譜面bytesを解析し、曲フォルダ全体の事前展開は不要です。
solid書庫では他の資源も順に復号しますが、スキャン用に保持しません。
登録・更新・同一譜面コピーの選択は[曲の取得元とスキャン](song-sources.md)を参照してください。

```powershell
bmz-player songs load "G:/BMS/OTHERS"
bmz-player "G:/BMS/OTHERS/set.zip!/song/chart.bms" -a
bmz-player -P "G:/BMS/OTHERS/set.rar!/song/chart.pms"
bmz-player export video "G:/BMS/OTHERS/set.7z!/song/chart.bmson" -o out.mp4
```

`!/` より前が元書庫、後ろが内部譜面です。相対指定では書庫部分だけを現在の作業ディレクトリから
絶対パスへ解決します。書庫名だけを再生コマンドへ渡した場合は、スキャンして選曲する案内を表示します。
全体同期後も保持する曲rootは `songs add` で登録してください。

## 資源と保存先

ライブラリDBとViewer IPCには元書庫と内部エントリ名を保持します。
画像・試聴・再生のworkerが必要に応じて `AppPaths.cache_dir/song-archives` へ展開します。
`BMZ_CACHE_DIR` を設定した場合もその配下を使い、スコアやリプレイに一時展開パスを保存しません。
譜面の MD5 / SHA-256 は内部譜面bytesから計算するため、通常フォルダにある同じ譜面と記録を共有できます。
同じ譜面bytesを含む別書庫でも、音源・画像・動画BGAは選択したコピーの資源を使います。

音源、BGA、STAGEFILE、BACKBMP、BANNER、PREVIEW は譜面のフォルダを基準に解決します。
`../shared/key.wav` のような書庫内の共有資源は利用できます。書庫外へ出る参照はエラーです。
画像・音声の拡張子補完と、PREVIEW未定義時の `preview*.wav` / `.ogg` 等の探索も行います。
明示試聴が見つからなければ、従来どおり譜面から試聴音声を生成します。

展開先は書庫内容のSHA-256で世代を分けます。資源だけの更新もファイル情報の変化から検出し、
選曲画像・明示試聴・生成試聴と次のプレイへ反映します。再生中の世代は置き換えません。
計算したSHA-256は、サイズ・更新日時・作成日時（Unixではinodeとctimeも）と組にして
ライブラリDBの `song_archive_fingerprints` に記録します。これらが一致する間は書庫全体を読み直さず、
Play開始時の確認もscan時の世代と一致すれば譜面エントリを展開しません。
展開を公開する前には書庫を再ハッシュし、記録と食い違えば記録を破棄してエラーにします。
リトライは再ロードし、Practiceの反復中はロード済み資源を維持します。
Practiceへ再入場、またはViewerのF5再読込で更新を反映できます。
世代情報のない音量解析DBキャッシュは書庫再生へ流用しません。

キャッシュの自動削除は行いません。不要な世代はプレイ停止中に削除できます。
削除後は次のロードで再展開します。欠損した通常ファイルなど復旧可能なキャッシュ破損は
`.invalid-*` へ退避して再生成し、キャッシュ内のリンクは拒否します。

F3は元書庫をファイルブラウザーで選択します。曲テキストを開く操作（既定は `9` / `Numpad9`）は、
同じ内部曲フォルダにある `.txt` をバックグラウンドで展開して開きます。

## 対応範囲と制限

ZIPはStore / DeflateとZIP64に対応します。RARは `rars 0.10.0`、7zは `sevenz-rust2` の
既定codecを使用し、外部の展開実行ファイルは不要です。通常のsolid RAR / 7zも対象です。
暗号化、分割書庫、自己解凍形式（SFX）、7zのanti-item、リンク・特殊ファイルには対応しません。
絶対パス、書庫外への `..`、危険な名前、重複エントリ、大小文字やUnicode NFC正規化で衝突する名前は拒否します。
書庫内の書庫をさらに曲rootとしてスキャンする処理は行いません。

Unicode指定がない従来のファイル名はUTF-8を優先し、次にCP932で読みます。
CP932の日本語に含まれる `0x5c` を区切り文字と誤認しないよう、文字列へ復号してから区切りを正規化します。

既定の読み取り上限は次のとおりです。

| 対象 | 上限 |
|---|---:|
| 書庫ファイル | 8 GiB |
| 展開後の合計 | 16 GiB |
| 1ファイル | 4 GiB |
| 1譜面 | 64 MiB |
| ヘッダー | 64 MiB |
| エントリ数 | 100,000 |
| 辞書 | 256 MiB |
| RAR reader作業領域 | 512 MiB |

辞書・reader作業領域は全方式の合計メモリ上限ではありません。RARでは利用ライブラリのresource policyへ
辞書・作業領域上限を渡し、7z本文ではLZMA / LZMA2 / PPMdのpropertiesを事前確認します。
7zの圧縮ヘッダー処理については、利用ライブラリの公開API上、
展開時メモリ使用量の厳密な上限までは保証できません。
