# 文章ガイド

BMZ Player の利用者向けの文章（ゲーム内の設定説明・通知、[マニュアル](../manual/README.md)、
IR Web の案内文）を書くときの基準です。
`docs/` の開発者向け文書には、末尾の[開発者向け文書](#開発者向け文書docs)の基準を適用します。

## 読み手

- BMS を初めて遊ぶ人が、用語集を見ながら読み進められることを目安にします。
- LR2 / beatoraja の経験者には、違いだけを短く示します。

## 文体

- です・ます調で、落ち着いた説明にします。「〜しましょう」「〜してみてください」は多用しません。
- 1文に1つの内容を書きます。日本語で60字前後を超えたら分けられないか検討します。
- 主語や対象を省略しすぎないようにします（「これを変更すると」ではなく「ゲージを変更すると」）。

## 書く内容

設定の説明は、次の順で必要なものだけを書きます。

1. その設定で何が変わるか
2. どういうときに変えるか、迷ったときのおすすめ
3. 変更が反映されるタイミングなど、知らないと困る注意点

項目名をそのまま言い換えただけの説明（「ゲージ：使用するゲージを選びます」）は書きません。
書くことがなければ、説明を空にしたほうが読みやすい場合もあります。

## 書かない内容

- 実装の経緯や以前のバージョンとの比較（「従来どおり」「新しい項目」「〜を維持します」）
- 内部名・設定ファイルのキー・crate名・feature名（`rule_mode`、`gilrs` の Button 番号など）
- 開発や計測でしか使わない情報。必要なら `docs/` の仕様へ置きます。

## 用語

- 判定名やオプション名は、ゲーム画面の表記に合わせます（`PGREAT`、`EX SCORE`、`HARD`、`S-RANDOM`）。
- 一般の人が知らない用語（緑数字、CN、閉店など）は、マニュアルの[用語集](../manual/ja/08-glossary.md)へ載せます。
- 同じものを別の言葉で呼びません。画面の表記を優先し、マニュアルもそれに合わせます。
- 画面上の操作は「設定 → ライブラリ → 曲フォルダ」のように、実際に押す順に書きます。

## 例

| 悪い例 | よい例 |
| --- | --- |
| プレイ開始時に使用するゲージを選びます。 | ゲージの増え方・減り方とクリア条件が変わります。初めての方は NORMAL、クリアが難しい曲は EASY がおすすめです。 |
| GPUのPresent Modeを選び、ティアリングと表示遅延のバランスを調整します。 | 画面のちらつき（ティアリング）を防ぐかどうかを選びます。防ぐ設定にすると、表示がわずかに遅れます。 |
| 既定のAutoは従来動作のままです。 | （書かない） |

## 他言語版

- 日本語版と同じ内容を、各言語で自然な文章にします。直訳で不自然になる場合は言い換えます。
- 英語は命令形や二人称（"Choose ..."、"You can ..."）を使い、簡潔にします。
- 韓国語は합니다体、中国語は丁寧で平易な書き言葉にします。
- 画面の項目名は、その言語のゲーム内カタログの表記をそのまま引用します。

## マニュアルの管理

- マニュアルの原稿は `manual/<言語>/NN-slug.md` に置きます。詳しくは [manual/README.md](../manual/README.md) を参照してください。
- 仕様を変えたときは、`docs/` の仕様に加えて、マニュアルとゲーム内の説明も確認します。

## 開発者向け文書（docs/）

`docs/`は、現在の仕様・操作・手順を開発者が確認するための文書です。
「文体」「用語」は利用者向けの基準と同じものを使い、以下の点だけを変えます。
「書かない内容」は適用せず、代わりに書く場所を分けます。

### 文体

- すべての文書をです・ます調で書きます。仕様・設計の文書も同じです。
- 箇条書きと表のセルは、体言止めや短い句で書いても構いません。文で書く場合はです・ます調にします。
- 1文に1つの内容を書きます。80字前後を超えたら分けられないか検討します。
  条件を3つ以上並べるときは箇条書きにします。
- 本文は日本語で書きます。ライセンス表記など、英語の原文を扱う文書は英語でも構いません。

### 構成

- 冒頭の2〜3文で、何の文書か、何を扱わないか、関連する文書を示します。
- 読み手が最初に必要とする情報を先に置きます。操作の文書なら操作表、
  仕様の文書なら概要と現在の値を先に置き、例外・詳細・互換・実装の入口は後に置きます。
- 見出しは内容を表す名前にします。「共通」「その他」「Notes」だけの見出しは使いません。
- 1つの仕様は1つの文書が管理します。他の文書では1〜2文の要約とリンクだけを書きます。
- 旧設定の移行や旧版との互換は「互換・移行」などの節にまとめ、現在の動作の説明と混ぜません。
- 日付付きの実装状況・計測結果・引き継ぎメモは`notes/`に置き、`docs/`からリンクします。
- 表・コードブロック・箇条書きの前後には空行を入れます。

### 内部名

- 設定キー・型名・ファイルパス・CLIオプションは書いて構いません。`` ` ``で囲みます。
- 操作や設定を説明するときは、画面の表記を先に書き、内部名は後ろの括弧に添えます。
  例：「BMZ メニュー → プレイ → RULE MODE」（`[play].rule_mode`）

### 表記

| 対象 | 表記 | 使わない表記 |
| --- | --- | --- |
| 画面名 | 選曲画面、決定画面、プレイ画面、リザルト画面 | Select画面、Decide中（コード上の状態名は`Select`のように囲みます） |
| F1の設定 | 「BMZ メニュー → ライブラリ → スキャン」 | 「F1の設定」「本体設定」「詳細設定」「`設定 > 入力`」 |
| 選曲画面の設定フォルダ | 「選曲画面の 設定 → 入力 → キーコンフィグ」 | 「ゲーム内設定」だけの表記 |
| 画面の項目名・ボタン | 「」で囲み、画面の表記どおりに書く | 言い換え |
| オプション値・判定名 | 画面の表記どおりで、囲まない（HARD、S-RANDOM、PGREAT） | Hard、hard（コード上の値は`Hard`のように囲みます） |
| 鍵盤 | KEY1〜KEY7、2P KEY1、Scratch Up / Down | Key1、Key8..14 |
| 補助ボタン | E1〜E4（各文書の初出で、既定のキーと役割を示すか説明へリンクする） | — |
| キーの組み合わせ | 同時押しE1+E2、押している間E1 hold、押しながら別のキーE1 hold + KEY1、一定時間押し続けるE1+E2長押し | 長押しの意味でのhold、E1 double press（E1 2回押しと書く） |
| 範囲 | 〜（U+301C）。コード・設定値の範囲は`1..=1000` | ～（全角チルダU+FF5E）、~ |
| 選択肢の列挙 | 半角スラッシュの前後にスペース（NORMAL / HARD） | 全角の ／、前後にスペースのない/ |
| 括弧 | 和文中は全角（）、コード・英文中は半角 () | — |
| 和文と英数字の間 | スペースを入れない。画面の表記を引用するときはその表記どおり | 文書ごとのばらつき |
| 単位 | 数値に続けて書く（300ms、20%）。`frames`など英単語の単位は前にスペースを入れる（256 frames） | — |
| 用語 | プロファイル、コントローラー、バックエンド、お気に入り | profile、コントローラー、バックエンド、favorite（コード上の名前を除く） |
