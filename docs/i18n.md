# 多言語対応

BMZ Playerの画面表示の対応言語と、翻訳カタログの管理方法をまとめた文書です。
文章の書き方は[文章ガイド](writing-style.md)を参照してください。

## 対応言語

BMZ Playerは次のUI言語に対応しています。

- `ja` — 日本語
- `en` — English
- `ko` — 한국어
- `zh-CN` — 简体中文
- `zh-TW` — 繁體中文（台灣）
- `zh-HK` — 繁體中文（香港）

プロファイル設定の`ui.language`には、これらの正規化したBCP 47コードのどれかを保存します。
入力された言語コードは、使う前に次のとおり正規化します。

- 日本語・英語・韓国語の地域別コードは、それぞれの基本コードへまとめます。
- 簡体字中国語は`zh-CN`、繁体字中国語は`zh-TW`、香港・マカオの中国語は`zh-HK`へまとめます。
- 不明な値は`ja`として扱います。

## 翻訳の対象

BMZが表示するデスクトップUI、アプリが出す通知、IRのWebサイトを翻訳します。
デスクトップとWebサイトでは、UIとメッセージ書式の要件が異なるため、カタログを分けています。

次の内容は翻訳しません。

- タイトル・アーティスト・ジャンル・サブタイトルなどの譜面情報
- コース名、難易度表名、ユーザー名、IRの提供元名
- ファイルパス、URL、DBの値、リプレイデータ、IRのpayload、署名付きJSON
- 第三者製・利用者のスキンの文字・画像・プロパティ名・ファイル選択肢
- 開発者向けログ、内部のエラー文脈、ライセンス本文

同梱のdefaultスキンとCLIは、現在の多言語対応の範囲外です。
ただし、本体が管理する選曲画面のDETAIL OPTIONSパネルは例外です。
ラベル・説明・状態・理由・ガイドはデスクトップのカタログを使い、1つのsnapshotでdefaultスキンとネイティブ表示の両方へ渡します。
このパネルの文言は日本語と英語がそろっています。韓国語と中国語のカタログでは、新しい説明文が翻訳待ちのため英語のままです。

`PGREAT`、`FAST`、`SLOW`、`EX SCORE`、`BP`、`BPM`などのゲーム用語は、英語の表記のまま使います。
訳語を使う場合は、この文書で定めてから使います。

利用者向けの[マニュアル](../manual/README.md)は、対応言語ごとにディレクトリを分けています。
IRのWebサイトは表示中の言語のマニュアルを表示し、その言語のページがない場合だけ英語を表示します。
BMZ メニューのサイドメニューにある「マニュアル ↗」は、表示中の言語のパスでマニュアルを開きます。
`zh-HK`のマニュアルは`zh-TW`版を元に、香港の語彙と`zh-HK`カタログの画面表記へ合わせています。

## フォールバック

すべてのカタログは、同じメッセージキーと引数を持つ必要があります。
実行時のフォールバックは、キーが欠けた場合の安全策としてだけ使います。

- `zh-HK` → `zh-TW` → `en` → `ja`
- `zh-TW`、`zh-CN`、`ko` → `en` → `ja`
- `en` → `ja`
- `ja`

保存する値や通信で送る値は、表示中の言語に依存させません。
表示用のラベルは描画時に解決します。ラベルをwidget ID、一覧の識別子、DBのキー、シリアライズするenumの値に使ってはいけません。

## カタログの管理

デスクトップのメッセージは`crates/bmz-player/src/i18n/locales/`に置きます。
日本語のカタログを基準とし、すべてのカタログが同じキーとFluentの引数を持つことをテストで確認します。
IRのWebサイトは、リポジトリ直下の`i18n/locales/`に独立したカタログを持ちます。
こちらはNuxtの型検査とIRのテストで確認します。

メッセージを追加するときは、次の点を守ります。

- 意味を表すキー名を付けます。
- 動的な値はformatterの引数として渡します。
- 譜面・スキン・利用者が入力した値は、カタログへ書き写さず引数として渡します。

デスクトップのキーが欠けている場合は、キー名をそのまま表示します。
これは、開発中に翻訳漏れを見つけやすくするためです。
