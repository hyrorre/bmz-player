# KaleidBeat拡張の実装契約

2026-11-07の仕様合意に基づく。実装と検証の進捗はこの契約と区別する。
対象はrian-eimu版LR2oraja Endless Dream（ED-rian）の実装済み拡張。
EDとの比較はKaleidBeat本体との完全互換を意味しない。

  head `0404fb6aed5b7d2e1eb2d06e37b77afb98cda6dd`から設計・実装・テストを選別する。

  使用パーサーrian-eimu/jbms-parser: `71bac5808ac2a7ee11df141e44a97381c1a36416`。
- 添付rianIRソースはGit情報なし。結合7zのSHA-256:
  `c0692c08773c487bb9b0dfb9e9a9b87a9bd050ee2c16573669a5f379d0ce43a9`。
  添付コードと本番デプロイの同一性は未確認。

LOADINGFILE/READYFILE等の旧PRの後続機能を、旧PRにあることだけを理由に追加しない。

## 解釈と判定

- 拡張子と実際の拡張利用を分ける。BMS/BME/BML/PMS/BMSON中の拡張も検出する。
- Beatoraja/Lr2Oraja/DXの既存rule_modeを維持する。判定窓等は各モードの既存規則を使い、
  新しいrule_modeは追加しない。追加ノーツの状態遷移は比較対象ED実装と照合する。
- AUTO/FORCEは既存6設定を維持する。AUTOは定義済みHLNを維持し、
  FORCE LN/CN/HCNは元HLNも指定種別へ変換する。HLNを選ぶ新設定は追加しない。
  元譜面の種類・適用設定・実効種類・外部APIの数値を別々に保持する。
- 旧式17/27フリーゾーンは非PMSで更新日時によらず解釈する。
  EDの年代判定とは意図的に異なる。コピー・ZIP展開・再スキャンで解釈を変えない。
  PMSの通常ノーツとしての17/27の解釈を維持する。
- 未対応・不正な拡張は可能な範囲で読み込み・プレイを続け、診断と実際の解釈を記録する。
  部分対応であることだけを理由にローカル保存・BMZ IR送信を禁止しない。

## 動的分岐

- RATEは `EX * 100 / (開始時DEFAULT採点数 * 2)`。全曲の固定分母を使用し、
  分母が0なら100。分岐後の結果ノーツ数や結果EX率とは別の値とする。
- 評価時刻Tより前の判定・見逃し・保持ゲージを進め、同時刻の分岐は同じ状態を参照する。
  Tの入力処理は評価後。早押し済みノーツ、開始済みLNとその終端を保護する。
- 次の未評価分岐T以降のBGMを先行予約しない。Tより前に鳴り始めた音の残響は維持する。
- 通常プレイ・コース・BATTLEは動的評価に対応する。BATTLEへの対応はEDとの差分。
  PracticeはDEFAULT固定。各モードの既存保存・IR制限は維持する。
- Replayは入力、seed、採択枝と評価位置、適用設定、解釈仕様、
  LAMP等の評価時の外部状態を保持する。保存枝の再生と選択条件の検証を区別する。
  分岐情報のない旧Replayを黙って正しい再現とみなさない。

## 保存とランキング

ローカルとBMZ公式IRは原本単位で集約する。既存のrule_mode・LN policy等の区分は維持し、
採択経路や部分対応の差による新しいランキング区分は作らない。
EX・BP・CB・ランプ等の各ベストが異なる経路のプレイに由来することを許容する。
各指標の元プレイと、各履歴の実際の採点数・採択枝・部分対応内容を保持し、
集約ベストを一回のプレイとしてReplay化しない。

原本SHA-256/MD5は変更しない。解釈情報・採択枝・仕様バージョンは別の付加情報とする。
DB/Replay/importのバージョンは実装開始時のmainから採番し、旧PRの番号を再利用しない。

## Providerごとの送信

| Provider | Kaleid拡張の扱い |
| --- | --- |
| BMZ公式IR | サーバーも対応し、拡張・部分対応を理由とする一律除外をしない。原本単位の既存ランキングへ集約する |
| rianIR | EDの送信条件とサーバーの契約を満たす結果を送る。実際のLN種別をcanonical-v1の0..4で表す。CONDITIONALは専用フラグと時間検査に反映する |
| BMS-IR | 既存のrule_mode・アシスト・バックフィル等の制限を維持。拡張子だけのBMC、既存と同じ意味の表示・音声拡張、整合するCNOBJ/HCNOBJ・終端音は個別に判定する。HLN（FORCE変換を含む）、動的分岐、ポーション、フリーゾーン、ダミー等の未確認条件と部分対応結果は保留する |

rianIRは採択枝を保存・区分しない。通常ランキングはSHA-256とbody、BMZ向けライバルAPIは
さらにLNモードで集約する。取得結果を同じ枝での成績とみなさない。
サーバーがHTTP成功を返すことだけを送信条件の根拠にしない。
EDの分岐後LNメタデータ更新漏れの可能性はfixtureで検証し、虚偽の種類を送らない。

複数拡張は各条件の積で判定する。通常送信・永続キュー・再送・手動同期・CLI・
バックフィル・コースに同じprovider判定を適用する。送信対象外は通信失敗と区別し、
無限再送しない。旧データの機能フラグ欠落を「拡張なし」と断定しない。
本番ランキングへのテスト送信・外部問い合わせ・本番サーバー変更は行わない。

## 検証の受入条件

- 最小BMS/BMSONで正常・不正構文、BASE、競合、静的RANDOMと動的未採択枝を検証する。
- HLNの境界時刻、再押下、始点見逃し、終点、保持ゲージ、音声、理論EXとBP/CBを検証する。
- 同時刻入力・複数分岐、LNを跨ぐ分岐、枝ごとの異なるノーツ数、ゼロ分母、
  BGM予約境界、途中終了、Replay再現、BATTLEとコースを検証する。
- 旧DB/Replay、原本単位のベスト集約、部分対応保存、provider別許可・拒否・再送を検証する。
- 通常BMS/BMSONと既存LN/CN/HCNの保存・IR・判定を回帰確認する。
- ED比較は同一譜面・入力・設定を使い、コード上の推定と実測を区別する。
  IRはローカル/モックで検証し、必要なRust workspaceとIR Webのチェックを実行する。

## 形式と解釈

| 機能 | BMS系 | BMSON | プレイ |
| --- | --- | --- | --- |
| BMC | スキャン・書庫内探索に.bmc追加 | — | 拡張子自体は採点規則ではない |
| HLN | LNMODE 4、HLNOBJ | info.ln_type=4、t=4 | 1本1採点、理論EX2 |
| 型付き終端 | CNOBJ/HCNOBJ/HLNOBJ | LN種別・音声領域 | 終端音を保持 |
| 動的分岐 | CONDITIONAL/WHEN/ELSEWHEN/DEFAULT/ENDCONDITIONAL | conditional_blocks | 未評価枝はDEFAULT、評価後に置換 |
| フリーゾーン | SF/SHは1拍、SG/SIは始終点、17/27は旧形式 | free_zone_channelsのx/y/l | 内部採点をゾーン1個に置換 |
| ポーション | F/G系 | potion_notes | 通過時の保持で生存ゲージ回復 |
| ダミー | H/I通常、J/K長押し、L/M地雷、N/Oポーション | 対応dummy配列 | 表示のみ |
| 小節線 | ST | lines | 描画のみ |
| 速度 | 既存SPEED/SCROLL | speed_eventsのy/rate | 既存速度処理へ接続 |

認識した未対応命令・不正拡張は診断へ残して無視する。未知ヘッダーすべてを必須拡張と
推測するわけではない。復元できないファイル破損、資源制限、音声デコード失敗まで
正常再生を保証しない。静的RANDOMを先に確定し、不採択枝の拡張は使用扱いにしない。
動的全候補はsource、変換・採択後はeffective、宣言だけはdeclaredに記録する。
OBJ競合はHLN > HCN > CN > LN。同位置の実ノーツはポーション・ダミーより優先。
OBJのBASE解釈は既存BMSパーサーと同じ。ポーション回復値はBASE62でもbase36。

## HLNの状態遷移

始点の表示判定は暫定。採点状態と保持ゲージ状態を分離する。

| 状態／イベント | 採点 | 保持・音声 |
| --- | --- | --- |
| 始点捕捉 | 始点評価を保留 | 譜面始点以降を積分、始点キー音 |
| 終点まで保持 | 始点評価で1回確定 | 保持終了、終端音 |
| 早離し | 既存LN規則で始点・離鍵を合成 | 非保持へ切替、ミュート |
| BAD離鍵→release margin内に再押下 | 保留を継続 | 元のサンプル位置から音声復帰 |
| release margin満了 | 合成評価を1回確定 | 終点まで保持ゲージ継続 |
| 始点見逃し | 遅BAD窓の1µs後にPOORを1回確定 | その時点から保持状態を追跡 |
| 確定後の押し直し | 再採点・追加コンボなし | 保持状態と音声だけを更新 |

保持時間を正、非保持時間を負として積分し、±200msを**超えた**時にゲージを更新する。
採点済みでも終点まで継続。増減量とrelease marginは既存rule_mode・鍵盤／スクラッチ
判定窓を使う。スクラッチHLNにはBSS終端反転採点を適用しない。
例: 始点1,000ms、終点2,000msをPGで捕捉・保持すると最初の更新は1,200.001ms、
2,000msにEX2・コンボ1が確定する。途中でBAD等に確定した後の押し直しはEXを増やさない。
BP/CBは確定した1回の判定を既存規則へ渡す。

## 新ノーツ・表示・配置

ゾーン内部の通常ノーツ・LNは入力・音声を処理するが、EX・コンボ・ゲージ・判定表示・
ghostを加算しない。LNの片端が内部なら両端を内部扱い、両端が外なら対象外。
ゾーン終端で内部全PGならPG、PG/GREATだけならGREAT、それ以外でスクラッチ入力が
あればGOOD、無ければPOOR。空ゾーンはAUTOならPG、手動は入力に応じGOOD/POOR。
ポーションは通過時の保持で回復し、0のHARD系ゲージを復活させない。AUTOでは回復せず、
キー音もない。ダミー・ポーションは採点数・密度・EX理論値・FC条件へ含めない。
同時刻では入力状態を反映し、地雷・ポーション通過、見逃し・ゾーン終了を処理する。

固定レーン置換はゾーンも動かす。S-RANDOM等はED同様ゾーンを動かさず内部ノーツを
配置し直す。ダミーLNは配置のレーン占有を持つ。EXTRA NOTEはダミー・ポーションを
除いてから生成する。地雷の保持と最終配置への生成は最新BMZ mainの仕様を維持し、
EDの地雷除去とは異なる。実ノーツ生成を既存アシスト判定へ反映する。
途中終了時の未通過ポーションは回復せず、未採点ゾーンは残ノーツに含める。

HLN画像は専用定義→HCN→LNへフォールバックする。JSON/Luaは
hlnstart/hlnend/hlnbody、hlnbodyActive/Reactive/Miss、LR2は
SRC_HLN_START/END/BODY、BODY_ACTIVE/REACTIVE/DAMAGE等を受け付ける。
ポーションは通常ノーツのRGBを反転しalphaを維持。ゾーンは暗赤色、ダミーは対応種別の外観。

## 分岐の時刻・集計・資源

| 値 | 定義 |
| --- | --- |
| SCORE | 確定済みEX |
| RATE | SCORE×50÷開始時DEFAULT採点数。ゼロ分母100、100で切り詰めない |
| COMBO/MAXCOMBO | この曲の現在／最大コンボ |
| PGREAT/GREAT/GOOD/BAD/POOR | 各確定判定のFAST+SLOW |
| MISS | EMPTY POORを含む既存BP |
| GAUGE | 評価直前に選択されているゲージ値 |
| LAMP | 開始時ローカルベストのClearType index |
| AUTO | 全レーンAUTOなら1、それ以外0。Replayは記録値 |

採点数が変わってもRATEとゲージのTOTAL・係数は開始時の値を維持する。
結果EX率の分母は採択譜面の実数。DEFAULT100個、EX60ならRATE30。
採択後200個になってもRATE30だが結果理論EXは400。DEFAULT0個ならEX0でもRATE==100。
途中終了の未評価枝はDEFAULT。コースはプレイ済み各曲の実数と未プレイ各曲のDEFAULTを合計。
未プレイ曲のIR判定にも、コース開始時に固定した静的RANDOM seedでの取込情報を使う。
別の枝を選び得るライブラリスキャン情報で代用しない。事前取込が失敗して根拠が欠ける場合は
診断を残し、ローカル／BMZ IRの既存保存条件を維持しながら外部providerへの送信を保留する。

評価T直前までを入力時刻順に処理し、同時刻全分岐を同一状態で選び、Tの入力・イベントを
処理する。評価済み境界より古い時刻で遅れて届いた実入力は境界まで時刻を進めて記録し、
分岐を巻き戻さない。OS配送遅延を消去する保証ではない。
将来のBPM/STOP、小節長、SCROLL/SPEED、BGM/BGAを置換し、既判定・早押し済みノーツ、
開始済みLN/ゾーンと元終端を保護する。境界前に発音した尾は継続、以降の旧枝BGMは予約しない。
BMSON音声区間は採択BPM/STOPで再計算するが発音済みvoiceの終了位置は変えない。

全候補の音声・BGAを事前列挙・ロードするためDEFAULTだけよりメモリを使用する。
分岐の直積は列挙せず、評価時に採択組合せから再構築して既判定状態を移す。
大規模譜面の実機レイテンシは別途計測が必要。Viewer途中開始はAUTO/Replay入力で
先行分岐を決定。同一配置リトライも前回枝をキャッシュせず同じseedのDEFAULTから開始する。
BATTLE相手の非Replay時計は復元済みのViewer開始位置から進める。保持・見逃し待ちがない
空白は次のノーツ／分岐まで飛ばし、全区間の1ms時刻配列を作らない。保持・判定待ちの
区間では既存の1ms刻みを維持する。

## 永続形式と検証証拠

- library.db 36→37: HLN構成とkaleid_json。取り込み版9→10で再スキャン対象にする。
- score.db 34→35: score_kaleid_playsへ履歴と同じtransactionで証拠を保存する。
- Replay 7→8: 入力・seed・配置・オプションに加え、採択枝、評価値、算出枝、基準／実採点数、
  開始時LAMP、判定窓、解釈版、終了時刻、手動終了を記録する。
- BMZ IR Web SQLite migration 0017: HLN構成・動的分岐・解釈情報を追加する。

証拠はplay_options.kaleidにも含め、device evidenceとは別に署名対象へ入れる。
BMZ IRのcharts.kaleidはversion・declared・sourceだけを保持し、effective・diagnosticsは
各プレイの証拠へ残す。譜面情報の版が欠落または0なら既知版へ更新できる。
旧実装が譜面単位へ保存したeffective・diagnosticsは次回送信時に除去する。
旧スコアの解釈版はunknown。再スキャンで過去の証拠を補完しない。
旧Replayは参考再生し、欠落・再計算不一致を診断する。記録枝の再生と正当性の証明は別。
DBを戻す際は整合したbackupを使い、user_versionだけを巻き戻さない。

## 機能別IR条件

| 原本・実効機能 | ローカル／BMZ IR | rianIR | BMS-IR |
| --- | --- | --- | --- |
| 拡張子だけBMC、表示・音声、小節線、CNOBJ/HCNOBJ終端音 | 既存条件で可 | 既存条件で可 | 解釈版が既知で整合すれば可 |
| HLN、HLNをFORCE LN/CN/HCNへ変換 | 可 | canonical 0..4と既存条件で可 | 保留。元HLNを隠さない |
| 通常LNをHLNへ変換 | 選択設定を提供しない | 同左 | 同左 |
| 分岐・フリーゾーン・ポーション・ダミー | 可 | ED実装とサーバー条件を満たす場合 | 保留 |
| ダミー等へEXTRA NOTE適用 | 既存アシスト制限 | 既存アシスト制限 | 元機能に基づき保留 |
| 複数拡張 | 各既存制限を満たせば可 | 各条件の積 | 各条件の積 |
| 部分対応・不正拡張 | 診断を残して可 | 同じ解釈が未確認の結果は保留 | 保留 |
| 解釈証拠のない過去結果 | 既存保存・同期条件 | 旧通常結果の既存条件 | 証拠不足で保留 |

「可」はAUTO/Practice/アシスト等の除外を解除しない。rianIR canonical LNは
0=なし、1=LN、2=CN、3=HCN、4=HLN。未変換は元構成、FORCEは実効種別を送る。
分岐はhas_conditionalを送り、RANDOM同様の時間検査除外を使う。
BMS-IRのBMZ専用APIでは同等契約が未確認。Javaプラグインのフラグを根拠に許可しない。
