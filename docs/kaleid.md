# KaleidBeat拡張の実装契約

KaleidBeat拡張の譜面について、BMZ Playerの解釈・判定・保存・Replay・IR送信が守る契約をまとめた文書です。
対象はrian-eimu版LR2oraja Endless Dream（ED-rian）で実装済みの拡張です。KaleidBeat本体との完全互換は扱いません。
IR・スコア保存・LN・スキン・EXTRA NOTEの各文書では、Kaleidに関わる節から本書へリンクしています。

本書は2026-11-07の仕様合意に基づきます。実装と検証の経緯は[ED-rian統合記録](../notes/2026/2026-11-07-kaleidbeat-ed-rian.md)、
[main統合記録](../notes/2026/2026-11-13-kaleid-main-bokutachi.md)、
[レビュー対応記録](../notes/2026/2026-11-14-kaleid-playback-review-fixes.md)を参照してください。

## 解釈と判定

- 拡張子と、実際に拡張を使っているかを分けて扱います。BMS / BME / BML / PMS / BMSON中の拡張も検出します。
- Beatoraja / Lr2Oraja / DXの既存の`rule_mode`を維持し、新しい`rule_mode`は追加しません。
  判定窓等は各モードの既存規則を使います。追加ノーツの状態遷移は、比較対象のED実装と照合します。
- AUTO / FORCEは既存の6設定を維持し、HLNを選ぶ新しい設定は追加しません。
  AUTOは定義済みのHLNを維持し、FORCE LN / CN / HCNは元のHLNも指定した種別へ変換します。
  元譜面の種類、適用した設定、実効の種類、外部APIへ送る数値は別々に保持します。
- 旧式の17 / 27のフリーゾーンは、PMS以外では更新日時によらず解釈します。
  EDの年代判定とは意図的に異なります。コピー・ZIP展開・再スキャンで解釈は変わりません。
  PMSでは、17 / 27を通常ノーツとする解釈を維持します。
- 未対応・不正な拡張があっても、可能な範囲で読み込みとプレイを続け、診断と実際の解釈を記録します。
  部分対応であることだけを理由に、ローカル保存やBMZ IRへの送信を禁止しません。

## 動的分岐

- RATEは`EX * 100 / (開始時のDEFAULTの採点数 * 2)`です。曲全体で固定した分母を使い、分母が0なら100とします。
  分岐後の結果のノーツ数や、結果のEX率とは別の値です。
- 評価時刻Tより前で、採点時計が到達した判定・見逃し・保持ゲージを条件に使います。同時刻の分岐は同じ状態を参照します。
  時刻Tの入力は評価の後に処理します。早押し済みのノーツ、開始済みのLNとその終端は置換から保護します。
- 次の未評価の分岐の時刻T以降のBGMは、先行して予約しません。Tより前に鳴り始めた音の残響は維持します。
- 通常プレイ・コース・BATTLEは動的な評価に対応します。BATTLEへの対応はEDとの差分です。
  PracticeはDEFAULTに固定します。各モードの既存の保存・IR制限は維持します。
- Replayは入力、seed、採択した枝と評価位置、適用した設定、解釈の仕様、
  LAMP等の評価時の外部状態を保持します。保存した枝の再生と、選択条件の検証は区別します。
  分岐の情報がない旧Replayを、正しい再現として扱うことはしません。

## 保存とランキング

ローカルとBMZ公式IRは、原本の譜面単位で集約します。既存の`rule_mode`・LN policy等の区分は維持します。
採択経路や部分対応の差で、新しいランキングの区分は作りません。

- EX・BP・CB・ランプ等の各ベストが、それぞれ異なる経路のプレイに由来することを許容します。
- 各指標の元のプレイと、各履歴の実際の採点数・採択した枝・部分対応の内容を保持します。
- 集約したベストを、1回のプレイとしてReplayにはしません。

原本のSHA-256 / MD5は変更しません。解釈情報・採択した枝・仕様のバージョンは、別の付加情報として持ちます。

## Providerごとの送信

| Provider | Kaleid拡張の扱い |
| --- | --- |
| BMZ公式IR | サーバーも対応済み。拡張・部分対応を理由に一律に除外せず、原本単位の既存ランキングへ集約する |
| rianIR | EDの送信条件とサーバーの契約を満たす結果を送る。実際のLN種別はcanonical-v1の0..4で表す。CONDITIONALは専用フラグと時間の検査に反映する |
| BMS-IR | 既存の`rule_mode`・アシスト・バックフィル等の制限を維持。拡張子だけのBMC、既存と同じ意味の表示・音声拡張、整合するCNOBJ / HCNOBJ・終端音は個別に判定する。HLN（FORCE変換を含む）、動的分岐、ポーション、フリーゾーン、ダミー等の未確認の条件と、部分対応の結果は保留する |

rianIRは採択した枝を保存・区分しません。通常のランキングはSHA-256とbodyで集約し、
BMZ向けのライバルAPIはさらにLNモードで集約します。そのため、取得した結果を同じ枝での成績とはみなしません。

- サーバーがHTTPの成功を返したことだけを、送信できる条件の根拠にはしません。
- EDでは、分岐後にLNのメタデータが更新されない可能性があります。fixtureで検証し、事実と異なる種類は送りません。
- 複数の拡張を使う譜面は、各拡張の条件をすべて満たす場合だけ送信します。
- 通常の送信・永続キュー・再送・手動同期・CLI・バックフィル・コースに、同じprovider判定を適用します。
- 送信対象外は通信の失敗と区別し、無限に再送しません。
- 旧データで機能フラグが欠けていても、「拡張なし」とは断定しません。
- 本番のランキングへのテスト送信、外部への問い合わせ、本番サーバーの変更は行いません。

## 検証の受入条件

- 最小のBMS / BMSONで、正常・不正な構文、BASE、競合、静的RANDOMと動的分岐の未採択の枝を検証します。
- HLNの境界時刻、再押下、始点の見逃し、終点、保持ゲージ、音声、理論EXとBP / CBを検証します。
- 同時刻の入力・複数の分岐、LNをまたぐ分岐、枝ごとに異なるノーツ数、ゼロの分母、
  BGM予約の境界、途中終了、Replayの再現、BATTLEとコースを検証します。
- 旧DB / Replay、原本単位のベストの集約、部分対応の保存、providerごとの許可・拒否・再送を検証します。
- 通常のBMS / BMSONと既存のLN / CN / HCNで、保存・IR・判定が変わらないことを回帰確認します。
- EDとの比較は同じ譜面・入力・設定を使い、コードからの推定と実測を区別します。
- IRはローカルかモックで検証し、必要なRust workspaceとIR Webのチェックを実行します。

## 形式と解釈

| 機能 | BMS系 | BMSON | プレイ |
| --- | --- | --- | --- |
| BMC | スキャン・書庫内の探索に.bmcを追加 | — | 拡張子自体は採点規則ではない |
| HLN | LNMODE 4、HLNOBJ | info.ln_type=4、t=4 | 1本で1採点、理論EXは2 |
| 型付きの終端 | CNOBJ / HCNOBJ / HLNOBJ | LN種別・音声領域 | 終端音を保持 |
| 動的分岐 | CONDITIONAL / WHEN / ELSEWHEN / DEFAULT / ENDCONDITIONAL | conditional_blocks | 未評価の枝はDEFAULT、評価後に置換 |
| フリーゾーン | SF / SHは1拍、SG / SIは始点と終点、17 / 27は旧形式 | free_zone_channelsのx / y / l | 内部の採点をゾーン1個に置換 |
| ポーション | F / G系 | potion_notes | 通過時の保持で生存ゲージを回復 |
| ダミー | H / I通常、J / K長押し、L / M地雷、N / Oポーション | 対応するdummy配列 | 表示のみ |
| 小節線 | ST | lines | 描画のみ |
| 速度 | 既存のSPEED / SCROLL | speed_eventsのy / rate | 既存の速度処理へ接続 |

- 認識した未対応の命令・不正な拡張は、診断に残して無視します。未知のヘッダーをすべて必須の拡張とは推測しません。
- 復元できないファイルの破損、資源の制限、音声のデコード失敗があった場合まで、正常な再生は保証しません。
- 静的RANDOMを先に確定し、採択されなかった枝の拡張は使用したものとして扱いません。
- 動的分岐の全候補は`source`、変換・採択後は`effective`、宣言だけのものは`declared`に記録します。
- OBJの競合はHLN > HCN > CN > LNの順で優先します。同じ位置では、実ノーツをポーション・ダミーより優先します。
- OBJのBASEの解釈は既存のBMSパーサーと同じです。ポーションの回復値は、BASE62でもbase36で読みます。

## HLNの状態遷移

始点の表示判定は暫定です。採点の状態と、保持ゲージの状態は分けて扱います。

| 状態／イベント | 採点 | 保持・音声 |
| --- | --- | --- |
| 始点の捕捉 | 始点の評価を保留 | 譜面の始点以降を積分、始点のキー音 |
| 終点まで保持 | 始点の評価で1回確定 | 保持を終了、終端音 |
| 早離し | 既存のLN規則で始点と離鍵を合成 | 非保持へ切り替え、ミュート |
| BADで離鍵→release margin内に再押下 | 保留を継続 | 元のサンプル位置から音声を復帰 |
| release marginの満了 | 合成した評価を1回確定 | 終点まで保持ゲージを継続 |
| 始点の見逃し | 遅いBADの窓の1µs後にPOORを1回確定 | その時点から保持状態を追跡 |
| 確定後の押し直し | 再採点・追加のコンボなし | 保持状態と音声だけを更新 |

保持している時間を正、保持していない時間を負として積分し、±200msを**超えた**ときにゲージを更新します。
採点済みでも、ゲージの更新は終点まで続けます。
増減量とrelease marginは、既存の`rule_mode`と鍵盤／スクラッチの判定窓を使います。
スクラッチのHLNには、BSSの終端の反転採点を適用しません。

例えば、始点1,000ms・終点2,000msのHLNをPGREATで捕捉して保持すると、最初の更新は1,200.001msです。
2,000msにEX 2・コンボ1が確定します。途中でBAD等に確定した後に押し直しても、EXは増えません。
BP / CBには、確定した1回の判定を既存の規則で反映します。

## 新ノーツ・表示・配置

### フリーゾーン

- ゾーン内部の通常ノーツ・LNは入力と音声を処理しますが、EX・コンボ・ゲージ・判定表示・ghostには加算しません。
- LNの片端が内部なら両端を内部として扱い、両端が外なら対象外です。
- ゾーンの終端を過ぎ、内部のノーツの判定が揃った時点で確定します。配置で移動したLNは、移動先での保持が終わるまで待ちます。
- 判定は、内部が全てPGREATならPGREAT、PGREAT / GREATだけならGREATです。
  それ以外は、スクラッチか移動先の内部ノーツへの有効な押下があればGOOD、無ければPOORです。
- 空のゾーンは、AUTOならPGREAT、手動なら入力に応じてGOOD / POORです。

### ポーションとダミー

- ポーションは通過時の保持で回復します。0になったHARD系のゲージは復活させません。
- AUTOではポーションで回復せず、キー音もありません。
- ダミー・ポーションは、採点数・密度・EXの理論値・FC条件に含めません。
- 同時刻では入力状態を反映してから、地雷・ポーションの通過、見逃し・ゾーンの終了を処理します。

### 配置

- 固定のレーン置換は、ゾーンも一緒に動かします。
- S-RANDOM等は、EDと同じくゾーンを動かさず、内部のノーツを配置し直します。
- ダミーのLNは、配置でレーンを占有します。
- EXTRA NOTEは、ダミー・ポーションを除いてから生成します。
  地雷の保持と最終配置への生成は最新のBMZ mainの仕様を維持し、EDの地雷除去とは異なります。
- 実ノーツの生成は、既存のアシスト判定に反映します。
- 途中終了したとき、未通過のポーションは回復せず、未採点のゾーンは残りのノーツに含めます。

### スキン

HLNの画像は、専用の定義→HCN→LNの順にフォールバックします。受け付ける定義は次のとおりです。

- JSON / Lua: `hlnstart` / `hlnend` / `hlnbody`、`hlnbodyActive` / `hlnbodyReactive` / `hlnbodyMiss`
- LR2: `SRC_HLN_START` / `SRC_HLN_END` / `SRC_HLN_BODY`、`SRC_HLN_BODY_ACTIVE` / `SRC_HLN_BODY_REACTIVE` / `SRC_HLN_BODY_DAMAGE`等

ポーションは通常ノーツの画像のRGBを反転し、alphaを維持します。
ゾーンは暗赤色の領域、ダミーは対応する種別のノーツと同じ外観です。

## 分岐の時刻・集計・資源

| 値 | 定義 |
| --- | --- |
| SCORE | 確定済みのEX |
| RATE | SCORE×50÷開始時のDEFAULTの採点数。分母が0なら100。100で切り詰めない |
| COMBO / MAXCOMBO | この曲の現在／最大のコンボ |
| PGREAT / GREAT / GOOD / BAD / POOR | 確定した各判定のFAST+SLOW |
| MISS | EMPTY POORを含む既存のBP |

### 採点数とRATE

採点数が変わっても、RATEとゲージのTOTAL・係数は開始時の値を維持します。
結果のEX率の分母は、採択した譜面の実際の採点数です。

- DEFAULTが100個でEX 60なら、RATEは30です。
- 採択後に200個になってもRATEは30のままで、結果の理論EXは400です。
- DEFAULTが0個なら、EX 0でもRATEは100です。

途中終了したときの未評価の枝はDEFAULTとします。リプレイでは採点の終了時刻と最後に評価した分岐の時刻のうち、遅い方をこのDEFAULTの確定時刻として記録します。
コースでは、プレイ済みの各曲の実数と、未プレイの各曲のDEFAULTを合計します。
未プレイの曲のIR判定にも、コース開始時に固定した静的RANDOMのseedで取り込んだ情報を使います。
別の枝を選び得るライブラリのスキャン情報では代用しません。
事前の取り込みが失敗して根拠が欠ける場合は、診断を残します。
その場合もローカル／BMZ IRの既存の保存条件は維持し、外部providerへの送信は保留します。

### 評価の時刻と譜面の置換

音声が評価時刻Tに達した更新で、Tより前の入力と譜面イベントを、その更新の採点時刻まで処理します。
そのスコアとゲージで同時刻の全分岐を選び、選んだ枝のBGMを予約します。Tちょうどの入力は評価後に処理します。
負の入力補正で採点が遅れているときは、まだ判定できるタップや通過前の地雷がTの手前に残ります。
これらは選択後も通常どおり採点します。後から届いた入力は元の判定時刻で採点し、選んだ枝は維持します。
リプレイには分岐ごとに評価時点の採点時刻と処理済み入力数を保存します。同じ採点時刻に届いた入力も、
実プレイと同じ順に分岐の前後へ適用します。分岐直後に中断した場合も、評価済みの枝を復元します。

- 将来のBPM / STOP、小節長、SCROLL / SPEED、BGM / BGAを置換します。
- 判定済み・早押し済みのノーツ、開始済みのLN / ゾーンと元の終端は保護します。
- 譜面を置換する前に、境界の直前までの未予約のBGM・自動キー音を旧譜面から予約します。
- 境界の前に発音した音の尾は鳴らし続け、境界以降は採択した枝の音を予約します。
- プレイ中と動画出力のノート分布・判定・FAST / SLOWのグラフは採択した譜面に更新し、既存の判定を反映します。
- BMSONの音声区間は採択したBPM / STOPで再計算しますが、発音済みのvoiceの終了位置は変えません。

### 資源と処理量

- 全候補の音声・BGAを事前に列挙・ロードするため、DEFAULTだけの場合よりメモリを多く使います。
- 分岐の直積は列挙しません。評価時に採択した組み合わせから再構築し、判定済みの状態を移します。
- 大規模な譜面での実機のレイテンシは、別途計測が必要です。
- 空白の区間は次のノーツ／分岐まで飛ばし、全区間の1ms刻みの時刻配列は作りません。
  保持・判定を待つ区間では、既存の1ms刻みを維持します。

### Viewer・リトライ・BATTLE

- Viewerで途中から開始した場合は、AUTO / Replayの入力で先行する分岐を決めます。
- 同じ配置でのリトライも前回の枝をキャッシュせず、同じseedのDEFAULTから開始します。
- BATTLEの相手のReplayでない時計は、復元済みのViewer開始位置から進めます。

### IRへ送る証拠

- 証拠は`play_options.kaleid`にも含め、device evidenceとは別に署名の対象へ入れます。
- BMZ IRの`charts.kaleid`は`version`・`declared`・`source`だけを保持します。`effective`・`diagnostics`は各プレイの証拠に残します。
- 譜面情報の版が欠けているか0なら、既知の版へ更新できます。
- 旧実装が譜面単位で保存した`effective`・`diagnostics`は、次回の送信時に除去します。

### 互換・移行

- DB / Replay / 取り込みのバージョンは実装開始時のmainから採番しており、旧PRの番号は再利用していません。
- mainのlibrary 37（取り込み失敗版）とscore 35（通常BESTの対象・機器別の索引）を先に適用します。
- main統合前の開発ブランチが使ったlibrary 37 / score 35は、Kaleidの列・テーブルで識別します。
  データを保持したまま、mainで不足する列を追加して38 / 36へ移行します。通常のmainのDBとは混同しません。
- FREQ・H-RANDOM設定等は、mainの保存・Replay条件を引き継ぎます。
- 旧スコアの解釈の版は`unknown`です。再スキャンで過去の証拠を補完することはしません。
- 旧Replayは参考として再生し、欠落と再計算の不一致を診断します。記録した枝の再生と、正当性の証明は別です。
- DBを戻すときは整合したbackupを使い、`user_version`だけを巻き戻すことはしません。

### rianIR

- canonical LNは0=なし、1=LN、2=CN、3=HCN、4=HLNです。
- 変換していない場合は元の構成を、FORCEの場合は実効の種別を送ります。
- 分岐を含む譜面は`has_conditional`を送り、RANDOMと同様に時間の検査から除外します。

### BMS-IR

BMS-IRのBMZ専用APIでは、同等の契約を確認できていません。Javaプラグインのフラグを根拠には許可しません。

### Bokutachi

HLNをFORCE LNへ変換した結果の送信は、2026-11-13のユーザー合意に基づくBMZ側の条件です。
Kaleid拡張全体がBokutachiに公式に受け入れられたことは意味しません。

- 元のHLNは保存の証拠に残し、原本のSHA256 / MD5を維持します。
- 採択した枝・解釈の版を表せないDirect Manualへ、独自のフラグを送って対応済みとは扱いません。
- 単曲・コースの各曲・段位・再送に同じ拡張の条件を適用します。段位の変換HLN曲も、事前に登録ノーツ数を照合します。
- ルール・アシスト・FREQ・静的RANDOM・キー変換等のmain側の制限は維持します。
- ランキングの取得・ライバル比較・過去履歴の一括送信は、mainと同じく未対応です。

詳細は[Bokutachi](bokutachi.md)、根拠は[main統合記録](../notes/2026/2026-11-13-kaleid-main-bokutachi.md)を参照してください。
