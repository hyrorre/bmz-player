# BMZ HLN 仕様

決定日: 2026-09-19。ユーザー指定により、始点評価は終了時に確定し、終点の離し判定は始点との総合評価とする（LNと同じ）。
**LNの採点処理とHCNの保持ゲージを組み合わせる**BMZの仕様。2026-09-19にHLNの取込・判定・BODY・描画・保存を実装した。Kaleidの判定処理との厳密な一致は要求しない。設定とスコア区分は [LN policy](ln.md) を参照。

### 対応範囲

- BMS/BMCの `#LNMODE 4` と `#HLNOBJ xx` を取り込む。RANDOM解決後の有効なヘッダを読み、元ファイルのhashを保持する。BMCもライブラリのスキャン対象とする。
- 現行のbms-rsにHLN型がないため、HLNヘッダと種別付きOBJをBMZのadapterで補完する。`#LNMODE` は最後の有効な1〜4、同じOBJコマンドの再定義は最後の有効なIDを採用する。各OBJを併用でき、同じID・位置での競合は記述順によらず `HLNOBJ > HCNOBJ > CNOBJ > LNOBJ` の固定順で優先する。marker自身は無音。重ね置きの複数音と競合は[BMZのOBJ・終端音仕様](long-note-end-sounds.md)に従い、Kaleidの厳密な互換性は要求しない。
- JSON/LuaのBMZ側fieldは `hlnstart`, `hlnend`, `hlnbody`, `hlnbodyActive`, `hlnbodyReactive`, `hlnbodyMiss`。LR2 CSVでは `SRC_HLN_START/END/BODY` と `BODY_INACTIVE/ACTIVE/REACTIVE/DAMAGE` を扱う。既存HCN/LN素材へのフォールバックを持つ。
- library DB migration 34、chart import version 11、Replay v8を使用する。HLNを含む元譜面のスコア・コースは、既存IRへ送信しない。
- BMSONは `info.ln_type: 4` とノートごとの `t: 4` をHLNとして取り込む。個別の `t` は譜面全体の `ln_type` より優先する。終端音は既存BMSON/LNと同じく終点位置の `up: true` を使用し、通常ノーツを暗黙に終端音へ変えない。
- ユーザー確認によりtype 4と上記JSON/Lua field名を確定した。LNOBJとHLNOBJに同じIDがある場合は記述順に関係なくHLNOBJを優先し、HLNOBJ未対応プレイヤー向けにLNOBJも併記できる。
- 以下のReplay seek / Practiceの記述は、それらの独立した開始・復元機能を追加するときにも維持する契約。今回追加した復元処理は既存Viewerの途中開始経路に接続している。

## 1. 定義と不変条件

**HLNは始点の評価を保持し、LNと同じく終了時に始点・終点を合わせて1回だけ採点する。BODYはHCNと同じ保持ゲージを持つ。**
ここでいう「終了時」は、終点まで保持した場合の終了、Releaseによる終了、または早離し保留の確定時を指す。採点が終了しても、BODYのゲージ更新は譜面の終点まで続く。

| 項目 | LN | CN | HCN | HLN（採用仕様） |
| --- | --- | --- | --- | --- |
| 1本の採点対象数 | 1 | 2 | 2 | 1 |
| 始点の評価確定 | 終了時に確定 | 始点 | 始点 | 終了時に確定 |
| 保持中の定期回復・減少 | なし | なし | あり | あり |
| 終点の離し判定 | 始点との総合評価 | 独立採点 | 独立採点 | 始点との総合評価 |
| 始点見逃しの採点 | POOR×1 | POOR×2 | POOR×2 | POOR×1 |
| 早離し後の押し直し | 既存ルール | 既存ルール | ゲージ回復可能 | LNの保留取消＋ゲージ回復。確定後は再採点なし |

- 始点では評価とタイミング差を保持し、EX・FAST/SLOW集計・コンボ・通常判定ゲージをまだ確定しない。最終評価の確定時に通常ノーツ1個分を反映する。
- BODYの回復・減少はゲージだけに作用する。GREAT/BADのゲージ係数を使っても、GREAT/BADの判定イベントは生成しない。
- 終点は独立した2個目の採点対象にしない。離しによる評価・FAST/SLOWは1本の総合評価へまとめ、判定イベントは始点IDで1回だけ発行する。
- `LongEnd` は総合評価の終点、形状、終端音のために保持する。採点済みを表すための架空のPGREATを終点IDへ入れない。
- 正常なpairは `start_time < end_time` を満たす。長さ0・逆順・終端欠損は取込診断の対象とし、判定エンジンで有効なHLNとして動かさない。

## 2. LNと同じ総合評価

判定窓、RANK/EXRANK、鍵盤/スクラッチ区分、入力オフセット、候補選択、終点の判定窓、release marginは、そのプレイのBMZ `RuleMode` と現行LNの経路を使う。Kaleid用の判定窓は追加しない。

### 始点評価の保持

1. 始点に対して通常判定として採用されたPressで、PGREAT/GREAT/GOOD/BADの仮評価・timing deltaを保持し、始点IDを捕捉済みにする。採点イベントとしてはまだ反映しない。
2. 始点を消費しないEMPTY POORは始点の捕捉に数えない。通常判定の候補選択が別ノーツを選んだ場合も、このHLNの始点は未捕捉のまま。
3. 始点が未捕捉で通常ノートのlate BAD終端を過ぎた場合は、LNと同じくその時点で1本分をPOORで確定する。終了まで採点を保留するのは始点を捕捉した場合であり、見逃しを譜面終点まで遅延させない。対応する終点への連鎖POORは行わない。
4. 見逃しの論理時刻は、既存の判定条件 `now > start + bad_slow_us` が最初に成立する時刻とする。固定窓のfixtureでは `start + bad_slow_us + 1µs`。フレームの到着時刻へ遅延させない。
5. 1本1採点を明確にするため、HLNではBADも始点を消費するが、即時採点せず終了時に使う仮評価として保持する。9K等の非消滅BAD・同じ始点の再取得はHLNへ適用しない。複数ノーツへBADを配るルールでも、この始点の仮評価を保持し、即時の採点ゲージは発生させない。この始点消費規則はBMZ HLN固有とし、既存LN/CN/HCNの挙動は変更しない。

始点前から押しっぱなしでもPressを自動生成しない。始点を取れなければPOORとなるが、その時点で押下中ならBODYは回復状態から開始できる。
極端に短いHLNでは、BODYが終わっても始点の通常判定窓は残す。終点以降に始点を捕捉した場合は、その入力時刻に始点の仮評価を最終評価として1回確定し、BODYのゲージを遡って計算しない。

### 終点・早離しとの合成

既存LNの [combine_ln_judgement](../crates/bmz-gameplay/src/judge/engine/helpers.rs) とRelease経路を共用する。始点評価を `Js`、始点deltaを `ds`、Release時刻を `r`、譜面終点を `e` とする。

- 終点まで保持した場合、または `r >= e` の場合、最終評価とdeltaは `Js, ds`。離す操作は必須ではない。
- `r < e` なら `de = r - e` をlong-note end窓で評価して `Je` を得る。窓外はPOORとして合成する。
- 基本の最終評価は `Js` と `Je` の悪い方。deltaは絶対値が大きい方を採用し、同値なら終点側を使う。
- 現行LNと同じく、早離しの合成結果がBAD/POORなら最終評価をBAD、deltaを `de` とする。始点見逃しのPOORはこの合成を通さない。
- 最終deltaの符号からFAST/SLOWを決める。評価が悪化する早離しなら、始点PGREATでもEXやコンボを失い得る。
- 早離しの合成結果がBADでrelease marginがあれば、LN同様に確定を保留する。猶予中のPressで保留を取り消して始点の仮評価へ戻る。猶予なし、または期限到達ならその総合評価を1回確定する。
- 猶予が譜面終点をまたぐ場合は、現行LNの終点通過処理と同じく、期限前に終点へ到達すれば始点の仮評価で確定する。期限と終点が同時刻なら期限側の確定を先に処理する。期限ちょうどのPressでは既に確定した結果を取り消さない。
- 一度最終評価が確定した後は、押し直しでスコアを回復させない。BODYのゲージと音量だけは譜面終点まで押下状態に従って更新する。

例: 始点PGREAT＋早離しGOODは最終GOOD、始点GREAT＋終点まで保持は最終GREAT。始点PGREAT＋大幅な早離しは最終BADとなり、確定後に終点まで押し直してもBADのまま。

## 3. BODYの状態と寿命

`s = start_time`、`e = end_time`、`h = 始点を捕捉した時刻、または始点見逃しを確定した時刻` とする。
BODYのゲージ有効区間は **`[max(s, h), e)`**。`max(s, h) >= e` ならBODY更新はない。
始点を早く取っても `s` より前には回復しない。始点が未捕捉・見逃し未確定の時間は回復・減少とも行わず、後から遡って加算しない。最終採点までBODY開始を待たない。

| 状態/操作 | 次の状態 | 採点 | BODYへの作用 |
| --- | --- | --- | --- |
| 始点前、または区間内でも始点未捕捉 | 待機 | まだなし | ゲージ停止 |
| 始点捕捉後、区間内で押下中 | 保持 | 仮評価を保持 | 回復方向へ積算 |
| 採点未確定の保持中にRelease | 非保持 | LN総合評価を確定、または猶予中として保留 | 以後の時間を減少方向へ積算 |
| 早離し保留中に猶予内Press | 再保持 | 保留を取り消し、最終採点を待つ | 以後の時間を回復方向へ積算 |
| 最終評価が確定した後のPress/Release | 再保持/非保持 | 確定結果を維持 | 押下状態に従う |
| 始点POOR後にPress | 再保持 | POORを維持 | 回復可能 |
| `e` に到達 | BODY終了 | 未確定ならLNの終了規則で1回確定 | 終点まで精算し、カウンタ破棄 |

- 早離しで最終BADが確定した場合、1本分の通常BADゲージとコンボ切断をその時点で適用する。その後のBODY減少とは別であり、最終判定と保持ゲージの両方が作用する。
- 押し直しに回数制限はなく、始点の成否にも依存しない。終点付近だけの特別な無条件回復も設けない。
- release marginは採点保留だけに作用する。BODYは猶予中も実際のReleaseから非保持状態へ切り替わり、カウンタを減少方向へ進める。
- 同じレーン上の次の通常ノーツを、HLN保持状態で判定不能にしない。総合評価の採点状態とBODY管理を分離する。
- 正規化後に同一レーンのHLN区間が重なっている場合もpairごとに状態を保持し、同じ押下状態を共有する。各BODYが独立に回復・減少する。別の始点を取るには通常どおり新しいPressが必要。

## 4. 保持ゲージ

現行 [HCNカウンタ](../crates/bmz-gameplay/src/session/hcn.rs) と同じ閾値・符号付き積分規則、および [ゲージ係数](../crates/bmz-gameplay/src/gauge.rs) を使う。HLNの時間積分は [専用更新器](../crates/bmz-gameplay/src/judge/engine/hln.rs) で行う。
各pairの符号付きカウンタ `c` は、有効区間開始時に0。押下時間を加算、非押下時間を減算し、押下状態が変わってもリセットしない。

```text
H = 200_000µs
c += held ? elapsed_chart_us : -elapsed_chart_us

while c > H:
    apply_hcn_hold()   // GREAT相当のゲージ変化 × 0.5
    c -= H
while c < -H:
    apply_hcn_drain()  // BAD相当のゲージ変化 × 0.5
    c += H
```

- 閾値は既存HCNと同じく厳密な `>` / `<`。±200,000µsちょうどでは発生せず、±200,001µsで1回発生する。
- 例: 非保持250msで減少1回・残り-50ms。続けて保持250msでは残り+200msで回復なし。さらに1µs保持すると回復1回となる。
- 終点までの経過時間を最後に精算し、閾値を超えた更新だけ適用して残余を破棄する。終点ボーナスや残余の比例配分はない。例: 有効区間1秒を押し続けた場合、回復4回・残り+200msを破棄する。
- TOTAL、ゲージ種別、guts、上限/下限、自動切替は既存 `GaugeState` に従う。増減量を固定%にせず、HLNを1採点対象として求めた実際のゲージ係数を使う。
- 複数回の更新は各tickの論理時刻順に適用する。閉店条件に達したら通常の失敗処理に入り、後続の回復で失敗を取り消さない。既存のゲージ自動切替はその処理に従う。
- 時間軸は表示補正前の譜面時刻。BPMやSPEEDは更新間隔を変えず、STOP中も譜面時刻が進むためBODY更新は続く。pauseで譜面時刻が止まる間は更新しない。再生速度変更時も譜面時刻の200msを使う。

### 入力とフレーム境界

現在のHCNはフレーム終端の押下状態から経過時間を処理している。HLNは、その実装上のフレーム依存を仕様として引き継がず、次の時刻で区間を分割する。

- 始点時刻、始点捕捉/見逃し確定時刻、Press/Release時刻、release margin期限、ゲージ閾値の超過時刻、終点時刻。
- 各時刻では、それ以前の押下状態で当該時刻までの経過時間を精算し、その後に状態を切り替える。
- 終点と入力が同時刻なら、旧HLNのBODY精算、release margin期限判定、未確定の総合評価の確定、BODY終了・終端音を先に処理し、入力を次ノーツや次HLNへ渡す。終点のReleaseで二重採点や余分な減少は発生しない。
- 始点とPressが同時刻なら始点評価を保持してBODYを開始し、その時刻以前のBODY更新は行わない。
- 同時刻の複数入力は記録済みsequence順、同時刻の複数pairのゲージ更新はlane index → start note ID順にする。イベント間で閉店判定する順序も固定する。
- 描画用の最新キー状態とは別に、経過区間を再現できる押下状態を持つ。1フレーム内のPress→Releaseや、フレームが始点/終点を丸ごとまたぐ場合も省略しない。

通常プレイ・Autoplay・Replay・オフライン動画出力・battleの相手側にも同じ更新器を使う。HCNと共通化する場合は既存HCNの回帰を別途確認する。

## 5. 押し直しとスクラッチ

- BODY区間内のPressはHLNの保持状態を更新する。LNの早離し保留を取り消すPressはその処理で消費し、別ノーツへ流さない。それ以外のPressは別の実ノーツが通常判定対象なら、その判定も行う。
- 実ノーツの通常判定に使われなかった区間内Pressに対しては、HCN同様にEMPTY POORとフォールバックキー音を抑制する。始点未捕捉なら、始点に対する通常判定を先に試す。
- 地雷・ポーション等の通過/入力効果は独立して処理する。HLNの押し直しを理由に地雷を無効化しない。
- 保持判定は入力変換後のレーン押下状態を使う。複数キー/デバイスが同じレーンを押していれば、すべてが離れるまで保持として扱う。
- 皿HLNの離し判定はLNと同じ方向付きRelease処理に従い、保持を開始した方向と無関係なReleaseは総合評価に使わない。逆方向Pressそのものでは終了せず、BSSの独立した終点判定と、その後30msの逆方向Press抑制は適用しない。BODYの回復判定はレーン押下状態を使うため、反対方向への回転でも回復できる。
- 終点で押しっぱなしでも終了するが、物理的な押下状態を勝手にReleaseへ変えない。次の通常ノーツは新しいPressで判定する。

## 6. キー音と終端音

### 始点音

- 始点をPressで取った場合、その入力時刻に通常キー音として再生する。BADでも同じ。始点音が複数なら同じHLNに属する音の組として扱う。
- 始点音を再生した後は、Releaseでミュート、再保持で現在の再生位置から音量を戻す。巻き戻し・再発音・ループはしない。既に音源末尾なら復帰しても音は鳴らない。
- 始点見逃し後に保持が始まった場合は、譜面始点時刻を音源の起点とし、現在の経過位置から再生する。見逃し確定時に既に押下中なら、その時点で同じ処理を行う。過去の音を先頭から鳴らし直さない。
- BODY終点で、押下中だった始点音は残りを自然に再生する。非押下でミュートされていた音は無音を保ち、BODYが終了しただけで突然音量を戻さない。現実装ではそのvoiceを無音のまま自然終了させる。早離しによる採点確定だけでは音声管理を終了しない。
- 音量制御の単位はHLNの発音インスタンス。同じWAVを共有するBGM・別ノーツ・別HLNの音量を巻き込まない。正規化時にHLN始点と各layerへ専用SoundIdを割り当て、decode済みPCMは既存loaderのpath cacheで共有する。
- ゲージ・採点は入力時刻で処理するが、音量変更コマンドは既存のフレーム単位の音声経路へ渡す。音量ゲートのsample単位の予約APIは今回追加していない。

### 終端音

正規化後のpairに明示的な終端音がある場合は、**譜面の終点時刻に1回だけ自動再生**する。始点の成否、終点での押下状態、早離し・押し直しに依存しない。
Release時に前倒しして鳴らさず、終端音のためのJudgeイベントも作らない。終端音がない場合は何も鳴らさない。
総合評価の確定時刻と終端音の再生時刻は分離する。LNの採点処理を共用しても、そのRelease時の終端音イベントをHLNで重ねて発行しない。
複数終端音は保持された音をそれぞれ1回再生する。HLNOBJのmarker自身は無音とし、同位置の通常WAVをすべて保持する。同じWAV IDの重複は1回にまとめる。

キー音自動再生設定では、始点音・終端音を譜面時刻に各1回再生し、押下によるミュート/復帰を行わない。通常キー音経路と自動終端音経路が二重発音しないようにする。
FAILED/終了後は既存の音声終了処理に従い、未到達の終端音だけを後から再生しない。

## 7. 集計・クリア・画面表示

- HLN1本はノーツ数1、理論EX2、最大コンボ1、ghost1要素。TOTAL・密度上の構造的な1ノーツは始点位置で数える。進行ノーツ数、EX、コンボ、ghost、判定分布は最終評価の確定時に始点IDへ1回反映し、タイミング統計には総合評価で選んだdeltaを使う。
- BODY長やゲージtick数、終点はノーツ数へ加算しない。LN表示数としては1本を数え、図形上の終点は描画に残す。
- 総合評価BAD、または始点見逃しPOORは、確定時に通常どおりBP・CB・コンボへ反映する。BODY減少自体はBP/CBを増やさず、コンボを切らない。
- 始点PGREATでも早離しで総合評価がBADとなれば、押し直してゲージを満たしてもそのHLNではFC・Perfect・MAXにならない。LNの猶予内で保留を取り消した場合や、総合評価がPGREATを維持した場合はMAXの可能性が残る。閉店・未達ゲージは通常どおりFAILEDを優先する。
- 最後のHLNが早離しで採点済みでも、その時点で曲を終了しない。BODY終点と残りの音声/終了余白まで進める。FC演出は全採点の確定と最後の実HLN終点を待つ。BODY中の閉店時、まだ最終評価が未確定なら未処理ノーツ1個として既存の途中終了集計に渡す。
- 判定文字、FAST/SLOW、コンボ加算、判定ボムはLNと同じ最終評価の確定イベントで1回表示する。始点捕捉は保持開始の表示に使い、採点表示を先行させない。独立した終点ノーツの判定演出は追加しない。

BODY素材の選択は次で確定する。表示上の回復/減少状態はカウンタの符号ではなく、その時刻の押下状態から決める。

| BODY状態 | 素材 |
| --- | --- |
| 始点前、または始点未捕捉・見逃し未確定 | INACTIVE |
| 保持中で、始点をPGREAT/GREAT/GOODで取り、BODYで非保持を挟んでいない | ACTIVE |
| 保持中で、始点BAD/POOR後、または一度離してからの保持 | REACTIVE |
| 始点捕捉済み、または始点見逃し確定後の区間内で非保持 | DAMAGE |
| 終点以降 | BODYを表示しない |

HLN素材 → HCN素材 → LN素材の順に部品ごとにフォールバックする。保持/非保持タイマーは既存HCN用のtimerへも供給し、状態変更時に表示timerだけをリセットする。ゲージカウンタはリセットしない。
終点キャップの表示は既存の `show_ln_tail_cap` 設定をLNと共有する。「LN・HLN終端キャップを表示」がOFFならHLNの終点キャップを描画せず、ONなら描画する。標準描画・スキン描画とも同じ条件を使い、BODY・始点・採点・終端音には影響しない。CN/HCNの終点キャップはこの設定の対象外。
同レーンに複数の有効BODYがある場合、部品状態はpairごと、レーンtimerの代表は始点時刻 → start note ID順で先のpairとする。ダミーHLNは非採点の表示物なので、このゲージ・音声処理には参加しない。

## 8. Autoplay・途中再生・保存

- Full AutoとAuto Scratch対象レーンは、始点時刻にPressし、終点まで保持する。終点でPGREATの総合評価を1回確定し、Releaseは入力状態を解放する。BODY中に80msの自動キー離しが作動しないようにする。
- Replayは始点・早離し・押し直しの入力列から同じゲージを再計算する。終点用の架空判定や架空入力は記録しない。Human/Auto/Replayで同じタイムスタンプ列なら同じ判定・ゲージ結果にする。
- Viewerの途中開始は既存の非採点プレビュー方針を継承する。開始点をまたぐHLNは始点を仮PGREATとして保持へ復元し、事前採点せず、終点で1回採点する。開始点より前に終点があるHLNだけをPGREAT×1として事前集計する。BODYカウンタは開始点で0とし、過去のBODYゲージを一括付与しない。終端音は終点が開始点以降にあるものだけ予約する。
- スコアを再現するReplay seekでは、Viewer用のPGREAT補完を使わない。入力の先行実行または状態snapshotで、始点の仮評価・総合評価の確定状態・早離し保留と期限・押下状態・BODYカウンタを復元する。
- Practiceで途中開始する場合も非保存とし、既存の練習ゲージ初期値と現在の入力状態でBODYを開始する。過去の始点失敗やBODYダメージを新規生成しない。
- `auto_ln/auto_cn/auto_hcn` は明示HLNを尊重する。既存 `force_ln/force_cn/force_hcn` はHLNも変換し、変換後の採点・ゲージ・終点音規則を使う。
- 初期実装ではprofileの `auto_hln/force_hln` 選択肢を増やさず、譜面で宣言されたHLNの対応を優先する。一方、明示HLNだけの譜面を正規化保存する `LnScorePolicy::ForceHln` は追加する。undefined混在時は既存Auto*のfallback区分を維持する。
- `has_defined_hln` / `defined_hln_pairs`、effective mode、score policy、ReplayのHLN対応版を保存する。旧データをHLNとして推測しない。外部IRがHLNに対応するまでは、HLNを含む元譜面のスコア・コースを送信しない。
