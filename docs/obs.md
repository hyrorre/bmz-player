# OBS WebSocket連携

BMZ Playerの画面に合わせて、OBSのシーン、ソースの表示、自動録画を操作できます。
設定はF1 → 連携・録画 → OBS WebSocketで行います。

## OBS側の準備

1. OBS Studioの「ツール → WebSocketサーバー設定」を開きます。
2. WebSocketサーバーを有効にします。OBS WebSocket v5が必要です。
3. ホスト・ポート・パスワードをBMZに入力し、OBS WebSocket連携を有効にします。
   同じPCで使う場合、ホストは`localhost`、標準ポートは`4455`です。
4. 「シーン一覧を取得」で接続を確認します。シーン内のソース候補も取得します。

接続状態、再試行までの時間、認証エラーは設定画面に表示します。
OBSが起動していない場合もBMZでプレイできます。接続はバックグラウンドで再試行します。
認証や接続先に誤りがある場合は、設定を修正して保存してください。

## コマンドを登録する

「追加」で行を作り、タイミングとアクションを選びます。
必要な名前は候補から選ぶか、直接入力します。
OBS未接続時も閲覧・編集・削除できます。候補にない保存済みの名前も保持します。

| アクション | 必要な指定 |
| --- | --- |
| シーン切り替え | 遷移先のシーン名 |
| ソースを表示 | ソースを配置したシーン名、ソース名 |
| ソースを非表示 | ソースを配置したシーン名、ソース名 |
| 録画開始 | なし |
| 録画停止 | なし |

同じタイミングのコマンドは、一覧の上から順に実行します。
上下の移動ボタンで順序を変えられます。「削除」は1行、「すべて削除」は全行を削除します。
名前の入力が揃っていない行は保存できますが、実行時にはスキップします。
最大512行を実行対象とします。

変更は自動保存されます。決定・プレイ・リザルト中に変更した場合は、
現在の録画の停止待ちと保持判定を保つため、次回起動時に反映します。
詳しくは[設定の保存と反映](settings.md#保存と反映)を参照してください。

## タイミング

| 対象 | 開始 | 終了 |
| --- | --- | --- |
| ゲーム本体 | `MAIN_START` | `MAIN_END` |
| 選曲 | `MUSICSELECT_START` | `MUSICSELECT_END` |
| 決定 | `DECIDE_START` | `DECIDE_END` |
| プレイ | `PLAY_START` | `PLAY_END` |
| リザルト | `RESULT_START` | `RESULT_END` |
| コースリザルト | `COURSERESULT_START` | `COURSERESULT_END` |

画面遷移では、遷移元の終了、遷移先の開始の順に実行します。
プレイ終了の通知が画面退出より早い場合、`PLAY_END`はその通知時に1回だけ発行します。
通常終了、FAILED、ゲージによる途中終了、手動退出、リトライ、
リザルトを経由しない退出、コースのステージ切り替えでも同じ単位で扱います。
同じPlay画面で次のプレイが始まる場合も、新しい開始として扱います。

`MAIN_START`は初回の接続・認証後に1回実行します。
初回接続前に複数画面を経由した場合、現在画面の開始だけを実行します。
再接続では過去の開始・終了を再実行せず、現在画面の開始に登録した
シーン切り替え・ソース表示だけを同期します。録画操作は再実行しません。
設定変更による接続の作り直しでも、`MAIN_START`と`MAIN_END`は発行しません。

`MAIN_END`は接続中の通常終了で実行します。OBSが切断中の場合は送信しません。
終了時の送信・応答待ちには上限があります。応答がない場合、
すべての終了コマンドが完了する前に接続を閉じることがあります。
強制終了やクラッシュでは終了コマンドの実行を保証しません。

## 設定例

### プレイ中のシーンとオーバーレイ

同じ「プレイ：開始」に、次の順で登録します。

1. シーン切り替え：`Gameplay`
2. ソースを表示：シーン`Overlay`、ソース`Playing`
3. ソースを非表示：シーン`Overlay`、ソース`Selecting`
4. 録画開始

「選曲：開始」に`Selecting`の表示と`Playing`の非表示を登録すると、
選曲へ戻ったときに表示を切り替えられます。
ソースの対象シーンは、現在表示中のシーンでなくても指定できます。

### 自動録画

「プレイ：開始」に録画開始、「プレイ：終了」に録画停止を登録します。
録画停止の待ち時間で、演奏後の映像を含める長さを設定します。
待機中に次のイベントや後続コマンドが来た場合は、先に停止します。
終了時の待ち時間は省略します。

録画の保持モードは、次のとおりです。

| モード | 保持する条件 |
| --- | --- |
| Keep All | すべて保持 |
| On Screenshot | スクリーンショット撮影で保持を指定 |
| On Replay | リプレイ保存で保持を指定 |

停止済みの直前の録画は、次の録画が始まるまで保持判断を待ちます。
条件に合う保持指定がなければ、次の録画開始時に直前のファイルを削除します。
最後の録画は次の開始がなければ残ります。
録画中のリトライでは一度停止し、Keep All以外では中断した録画を削除して再開します。
保存先はOBS側で設定してください。削除できるのはBMZから参照できるローカルファイルです。

## 旧設定との互換性

`obs.rules`がない設定は、従来の`obs.scenes`と`obs.actions`を使用します。
コマンド一覧を初めて変更したとき、各画面のシーン切り替え、録画操作の順に移行します。
`PLAY_ENDED`は`PLAY_END`、ほかのキーは各画面の`START`へ対応します。
閲覧と一覧取得だけでは移行しません。

新形式の一覧があれば、旧設定は実行しません。空の`rules = []`も新形式です。
「すべて削除」しても旧設定は復活しません。
ホスト・ポート・パスワード、録画保持モード、停止ディレイは変えません。

TOMLの例:

```toml
[[obs.rules]]
trigger = "PLAY_START"
action = "SwitchScene"
scene_name = "Gameplay"

[[obs.rules]]
trigger = "PLAY_START"
action = "ShowSource"
scene_name = "Overlay"
source_name = "Playing"

[[obs.rules]]
trigger = "PLAY_START"
action = "StartRecord"

[[obs.rules]]
trigger = "PLAY_END"
action = "StopRecord"
```

## トラブルシューティングと対応範囲

- 接続できない場合：OBS側のサーバー有効化、ホスト・ポート・パスワードを確認します。
  別PCのOBSではファイアウォールも確認してください。
- シーン・ソースが見つからない場合：一覧を再取得し、OBS上の名前と一致するか確認します。
  保存済みの名前は自動削除しません。
- ソースが切り替わらない場合：指定したシーンに直接配置された項目か確認します。
  グループ自体の表示は操作できますが、グループ内部の再帰列挙・操作には対応しません。
  入れ子のシーンの内部項目は、そのシーンを対象に指定します。
- 同じソースを同じシーンに複数配置した場合：OBS APIの`searchOffset = 0`で最初に一致する項目を操作します。
  別シーンに同名ソースがある場合は、指定したシーン内だけが対象です。
- コマンドが失敗した場合：接続エラー欄とログを確認します。独立した後続コマンドは続行します。
  応答待ちは1要求2秒、シーン準備待ちの再試行は最大8回です。
- 画面がすぐに変わった場合：古い画面の未実行の表示操作と、古いソースID取得への応答を破棄します。
  すでにOBSへ送信した操作を取り消すことはできません。
- OBS切断中に行った録画開始・停止は、再接続時に再生しません。OBS側の実際の録画状態を確認してください。

通信と応答待ちはTokioタスクで行い、ゲームのフレーム処理では待ちません。
任意API、フィルター、音声ミキサー、リプレーバッファの追加制御には対応しません。
API仕様は[OBS WebSocket v5 protocol](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md)を参照しています。
