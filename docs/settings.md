# 設定画面（BMZ メニュー）

F1で開くBMZ メニューの構成と、各ページの設定の仕様をまとめた文書です。
キー操作は[操作方法](controls.md)、利用者向けの説明は[マニュアル](../manual/README.md)を参照してください。

## 構成

BMZ メニューは、本体・プロファイル・スキンの設定とツールをまとめた1つのウィンドウです。

- 左のサイドメニューで、一般 / プロファイル / 音声 / 映像 / 入力デバイス / キーコンフィグ / プレイ / 選曲 / スキン / ライブラリ / 難易度表 / IR / 連携・録画 / データ移行を選びます。
- その下の「ツール」欄には、譜面ダウンロード / コース作成 / Random Trainer / デバッグ表示が並びます。
- 「マニュアル ↗」とライセンス表記は、サイドメニューの最下部に固定しています。「マニュアル ↗」は、BMZ IRの`/manual`を表示中の言語でブラウザで開きます。
- ウィンドウの幅が狭い場合は、左のメニューがカテゴリを選ぶプルダウンになります。
- ページごとにスクロール位置を保持します。
- 譜面ダウンロードの一覧は右側に余白を設け、一覧とページ全体のスクロールバーを離して配置します。

一部のページは、複数の内容を1ページにまとめています。

| ページ | 内容 |
| --- | --- |
| プレイ | プレイ・判定・表示・リプレイの各セクション |
| ライブラリ | 曲フォルダ・スキャン・譜面取得の各セクション |
| IR | IRの提供元の設定・スコアの一括操作・IR送信キューを縦に並べて表示 |
| 連携・録画 | Discord・OBS WebSocket・スクリーンショットを縦に並べて表示 |
| データ移行 | 上部のプルダウンで内容を切り替え |

## 保存と反映

OBSの接続手順・コマンド登録・設定例は[OBS WebSocket連携](obs.md)を参照してください。

- 設定は、変更が止まってから約0.5秒後に自動で保存します。設定を閉じるときにも保存します。
- プレイの終了・リトライ・アプリの終了時にも、本体設定とプロファイル設定の両方を保存します。
- 保存に失敗した場合は、ウィンドウ下部に表示し、5秒間隔で再試行します。
- 音声出力の「適用」など、その場で実行する操作は、各ページのボタンから行います。
- 最大FPSは、スライダーのドラッグ中には反映せず、マウスを離したときに反映します。数値を直接入力した場合は、Enterを押すか入力欄からフォーカスを外したときに反映します。

決定画面・プレイ画面を表示中の扱いは次のとおりです。

- 一般・音声・映像・連携・録画のページは、編集・保存できます。
- 音声出力の「適用」は、選曲画面へ戻るまで保留します。ASIOデバイスの更新は、演奏中は使えません。
- OBSの設定を決定画面・プレイ画面・リザルト画面の表示中に変更した場合は、その後の変更も含めて次回の起動時に反映します。現在の録画の停止待ちと保存の判定を保つため、今回の起動中は変更前の設定を使い続けます。
- ほかのページは変更できる項目が限られますが、ページの移動と閲覧はできます。

キーの割り当ての入力待ちは、別のカテゴリ・ページへの移動や、設定ウィンドウを閉じる操作で解除します。

## 一般

- UI設定の下に、更新・ログの設定を表示します。
- 「ディレクトリを開く」から、resource / data / cache / logsの各フォルダを開けます。
- UI倍率は、プルダウンで100・125・150・175・200%から選べます。OSの表示倍率に加えて適用し、BMZ メニュー・設定・プラクティスなど、eguiで描く補助UI全体を拡大します。プレイスキンには影響しません。
- UI倍率の変更はすぐ反映し、プロファイルに自動で保存します。既存のプロファイルの既定値は100%です。
- 言語のラベルは、英語以外では「言語 (Language)」のように英語を併記します。

新規プロファイルと、`ui.language`を省略したプロファイルでは、OSの優先言語の順に、最初の対応言語を選びます。
対応言語がない場合は英語になります。
保存済みの言語の指定はOSより優先します。選択した後の言語コードを保存するため、OSの言語を変えても上書きしません。
対応言語とカタログの管理は[多言語対応](i18n.md)を参照してください。

## プロファイル

選曲画面では、「BMZ メニュー → プロファイル」のプロファイル管理で切り替え先を選び、「切り替える」を押すと、再起動せずにプロファイルを変更できます。
新規作成・複製のときも「作成後に切り替える」を選べます。

切り替えは次のように進みます。

1. 現在の編集を保存します。
2. 現在の選曲画面を表示したまま操作を一時停止します。
3. 切り替え先の選曲スキンの準備と、IR送信中の1件の完了を待ちます。
4. 切り替え先の設定・スコア・お気に入り・IR・スキンを読み直し、プロファイルとスキンをまとめて切り替えて、選曲画面のルートへ戻ります。

- 切り替えた後は通常プレイになり、選曲の絞り込み・並び順は切り替え先の保存値を使います。
- 切り替えに成功したプロファイルを、次回の起動でも使います。`--profile`を指定して起動しただけでは、次回の起動設定は変わりません。
- スキンを含む読み込み・保存に失敗した場合は、現在のプロファイルを維持します。
- 決定画面・プレイ画面・リザルト画面、Viewer、取り込み・ログイン・コース編集などの処理中は、切り替えできません。

## 音声

- BGMと自動キー音は、常にシステム時計の予定時刻で先読み予約します。音声側は各出力バッファの時刻対応から開始位置を決めます。平均の出力遅延は押鍵音と同じになるように揃えます。フルオートにも適用します。
- 押鍵に応じたキー音・判定ガイド音・システム音は即時要求です。判定とノーツ表示にはシステム時計を使います。
- 先読み予約の切り替え項目はありません。旧設定の `audio.schedule_ahead = false` は無視し、次の保存時に削除します。
- 先読み予約は音の開始位置を制御します。再生中の長いWAV自体の速度補正や、デバイス・モニターの物理遅延の自動校正は行いません。長いBGMのWAVはデバイスの速度で進むため、曲の後半ほどノーツや後から鳴る音とわずかにずれることがあります。開始位置の平均は旧方式と同じなので、既存の判定・表示オフセットはそのまま使えます。

### 出力バッファ

- 「BMZ メニュー → 音声」のFixedバッファは、16〜4096 framesで指定できます。プリセットは16 / 32 / 48 / 64 / 96 / 128 / 256です。
- 機器の対応範囲外の値は、範囲内へ調整します。
- WASAPI排他では指定値を優先し、デバイスの最小値より小さい場合は最小値へ補正します。
- 初期化に失敗した場合は、デバイスの既定の周期、その2倍の順に切り替えます。
- 「動作中」には、バックエンド・デバイス・サンプルレートを表示します。実際のバッファの値は、音声の診断ログで確認します。
- 既定値は、バックエンドが`Auto`、バッファが256 framesです。
- 機器の抜き差しや出力形式の変更の後に音が出なくなった場合は、音声設定を再適用してください。

### macOSのCore Audio IOProc

- macOSの`Core Audio IOProc`は、通常のビルドで選べます（`experimental-coreaudio-ioproc` featureは既定で有効です）。
- `Auto`と`Core Audio`はCPAL / Audio Unitの経路を使います。IOProcは明示的に選んだ場合だけ使います。
- IOProcでも、出力デバイス・サンプルレート・バッファ・出力チャンネルは、ほかのバックエンドと共通の設定を使います。
- IOProcは入力streamのない機器専用です。入出力一体のUSB機器などでは`Core Audio`を選んでください。

詳しくは[macOS遅延検証](macos-latency.md#core-audio-ioproc実験用)を参照してください。
LinuxのPipeWireの選択と、比較の手順は[Linux遅延検証](linux-latency.md)を参照してください。

### 音量の正規化

- 譜面・プレビューの音量の正規化と、システムBGMの音量の正規化は、それぞれ切り替えられます。
- システムBGM側は、ループするシステム音源と、単発の決定音が対象です。そのほかの単発音には適用しません。
- 通常の名前のRESULTの音源は、単発のままシステム効果音の音量を使います。
- 選曲・RESULTの`.enter`入場音はシステム効果音の音量、`.loop`音源はシステムBGMの音量を使います。
- どちらも実行中に切り替えられます。OFFにしても解析済みのゲインを保持するため、もう一度ONにすると同じゲインをすぐ適用します。

### サウンドセット

「サウンドセット ルート」には、選曲・決定のBGMと任意のSEをまとめたセットを置けます。
セットに`clear` / `fail` / `a` / `aa` / `aaa`を追加すると、今回の結果に対応するRESULT BGMを使えます。
配置・優先順位・補完・子フォルダの抽選は[サウンドセットとシステム音](system-sound.md)を参照してください。

## 入力デバイス

### ゲームパッド

- ゲームパッドのバックエンドは、`自動選択` / `gilrs`から選べます。Windowsでは、HID reportをイベント駆動で受け取る`Raw Input`も選べます。
- `自動選択`は現在gilrsを使います。Raw Inputは明示的に選んだ場合だけ使います。
- 登録・初期化に失敗した場合は、gilrsへ切り替えます。
- バックエンドの変更は次回の起動から、1P / 2Pのコントローラーの割り当ての変更は次にプレイを開始したときから反映します。プレイ中（読み込み中・プラクティスを含む）の抜き差しや入れ替えでは、そのプレイの1P / 2Pは変わりません。

### アナログスクラッチ

「BMZ メニュー → 入力デバイス」または「選曲画面の 設定 → 入力 → 入力デバイス」では、`gamepad1`（1P） / `gamepad2`（2P）ごとに`ANALOG SCRATCH`、アナログ感度、アナログ停止閾値を変更できます。
変更は、動作中のゲームパッドのバックエンドへすぐ反映します。

- `ANALOG SCRATCH`がONの場合は、軸の回転の差分を、スクラッチ入力と、回転量に比例したメニューのスクロールに使います。
- OFFの場合はbeatorajaと同様に、軸の値が`> 0.9`の端を`AxisN+`、`< -0.9`の端を`AxisN-`の通常のボタンとして扱います。比例したスクロールは行いません。
- 割り当てのないSP用のゲームパッドは、1Pの設定を使います。
- 選曲・設定・IR順位表のアナログスクラッチでの移動は、軸の移動量で処理します。同じ軸から作られる押下イベントでは、重ねて移動しません。これは各ゲームパッドのバックエンドで共通です。

### キーボードのバックエンド（macOS / Linux）

macOSでは、キーボードのバックエンドで`winit`と、独立して取得する`GCKeyboard`を切り替えられます。

- `macOS IOHID`は、`macos-iohid` featureを有効にしたビルドでだけ選べます。通常のビルドには含めません。
- GCKeyboardはmacOS 11以降で使え、入力監視の許可は求めません。
- 文字入力・IMEにはwinitを使います。既定の`Auto`はwinitで入力を取得します。

macOSのゲームパッドのバックエンドの`GameController`は、macOS 11以降で使えます。

- macOS 14以降は入力履歴とOSの時刻、macOS 11〜13はコールバックを受け取った時刻を使います。
- gilrsのButton / Axis番号は自動で移行しないため、切り替えた後はキーを登録し直してください。
- GameControllerでの機器の選択は実行中だけ有効で、再起動すると解除されます。複数台のときは、入力デバイスの画面で1P / 2Pを明示的に選んでください。
- 対応していない機器にはgilrsを使います。

権限・対応キー・フォールバックとA/B試験は[macOS遅延検証](macos-latency.md)を参照してください。

Linuxの「BMZ メニュー → 入力デバイス」では、任意ビルドの`Linux evdev (X11)`と対象のデバイスを明示的に選べます。

- 実際の動作、使えない理由、「winitに戻す」を同じ画面に表示します。
- Linuxのコントローラーの取得は、イベント待機方式を使います。

フォーカス・権限の制約と比較の手順は[Linux遅延検証](linux-latency.md)を参照してください。

### バックエンドの選択肢

- 選択肢には、現在のOS・バージョン・有効なfeatureで使えるものだけを表示します。Raw InputはWindowsだけ、GCKeyboard / GameControllerはmacOS 11以降だけです。
- 別のOSの設定やfeatureが無効なものなど、対応していない設定を読み込んだ場合は、キーボードを`Auto`、ゲームパッドをgilrsへ戻します。
- 設定欄には接続状態と必要な操作の案内を表示し、時計・文字入力の方式・遅延検証の説明は表示しません。
- IOHIDの許可ボタンは未許可の場合だけ、再試行の案内は許可が足りない場合・エラーの場合だけ表示します。

## キーコンフィグ

「BMZ メニュー → キーコンフィグ」では、共通 / 選曲 / プレイ / リザルトと、4K / 5K / 6K / 7K / 8K / 9K / 10K / 14Kの割り当てを変更できます。

1. 対象と入力スロットを選びます。
2. 現在値のボタンを押してから、キーまたはコントローラーを入力します。
3. Escapeで入力待ちをキャンセルし、Delete / Backspaceまたは「解除」で割り当てを削除します。

- 「デフォルトに戻す」は、表示中のカテゴリと入力スロットの行だけを初期値へ戻します。ほかのカテゴリ・キーモードは変更しません。
- 決定画面・プレイ画面の表示中は変更できません。
- コントローラーのレーンを「解除」すると、そのレーンは明示的な未割り当てになり、プロファイルに`control = ""`の行として保存します。行には`(none)`と表示します。
- 明示的な未割り当てのレーンをもう一度「解除」すると、そのレーンは「設定なし」に戻ります。7K / 14Kの選曲入力では、14Kの2P側の「設定なし」のレーンは同じ2P機器の7Kのレーンを、7Kの`CONTROLLER`の「設定なし」のレーンは1P機器の14Kの1P側のレーンを使います。行には`(SELECT 7K: Button1)`のように表示します。プレイ中は、プレイの設定対象モードの割り当てだけを使います。
- 「デフォルトに戻す」は、そのレーンを既定の割り当てへ戻します。既定の割り当てがないレーンは「設定なし」に戻ります。
- `KEYBOARD`と`KEYBOARD SUB`は独立したスロットとして保存します。`KEYBOARD`を未割り当てのまま、`KEYBOARD SUB`だけを使うこともできます。
- スクラッチの方向は、`Scratch Up` / `Scratch Down`の割り当てで指定します。
- 選曲の`FAVORITE SONG` / `FAVORITE CHART`（既定F8 / F9）は、単曲・コース曲間リザルトでも同じ割り当てを使います。コース最終リザルトではお気に入りを変更しません。

共通のE1〜E4などの操作には、`CONTROLLER`（どのコントローラーでも可）に加えて、`CONTROLLER 1P` / `CONTROLLER 2P`の入力スロットがあります。

- `CONTROLLER 1P` / `CONTROLLER 2P`を設定していない側は、`CONTROLLER`の割り当てを使います。行には`(COMMON: Button9)`のように表示します。
- `CONTROLLER 1P` / `CONTROLLER 2P`を設定すると、その側だけ`CONTROLLER`の割り当ての代わりに使います。もう一方の側の設定は変わりません。
- 片側で「解除」すると、その側は未割り当てになります。`CONTROLLER`の割り当ても使いません。行には`(none)`と表示します。
- 「デフォルトに戻す」は、その側の個別の割り当てを削除し、`CONTROLLER`の割り当てを使う状態へ戻します。
- 1P / 2PのE1〜E4は別々に押下を追跡します。1PのE1を押しながら2PのE2を押す、といった両側にまたがる組み合わせも使えます。

割り当てが重なった場合は、次のように処理します。

- 共通のE1〜E4と同じキーを選曲 / プレイ / リザルトへ割り当てた場合は、共通のE1〜E4を優先します。
- プレイ中に、キーモード別の鍵盤・スクラッチと、共通またはプレイの操作が重なった場合は、キーモード別の設定を優先します。
- 重なっている行には警告アイコンを表示し、割り当て自体は保持します。

## プレイ

「BMZ メニュー → プレイ」では、beatoraja互換の7つのアシストと、SCROLL / LONGNOTE / MINE / EXTRA NOTEのモディファイアを設定できます。

EXTRA NOTE DEPTHは、同時刻にBGMから追加するノーツ数の上限です。
LN・地雷や前後のノーツとの衝突、同時押しと局所密度を検査し、配置できない音はBGMに残します。
実際に追加された場合だけアシスト扱いになります。詳細は[EXTRA NOTEの配置仕様](extra-note.md)を参照してください。

- 「プレイ」セクションでは、判定ごとのGUIDE SEと、未処理のノーツの判定ラインでの滞留を設定できます。
- 「表示」セクションでは、ノーツの表示時間、CONSTANT、CONSTANTのフェード時間を設定できます。CONSTANTはプラクティスでは無効です。
- 「表示」セクションの最後にある「HS変更時のアニメーション時間」は、0〜1000ms、既定150msです。曲中のHS変更で、ノーツ・LN・小節線などの位置を、終わりに向けて減速するアニメーションで移動します。全キーモード共通の `lane.hispeed_transition_ms` にプロファイルごとに保存し、変更は現在の演奏へすぐ反映します。移動中なら現在位置から変更後の時間で移動し、0msにするとその場で移動を完了します。
- その下の「E2+鍵盤による緑数字の操作を反転」をONにすると、プレイ中のE2 hold + 鍵盤で、緑数字を上げる鍵盤と下げる鍵盤を入れ替えます。既定はOFFです。プロファイルごとに `input.invert_e2_key_green_number` へ保存し、変更はすぐ反映します。詳細は[プレイ画面の操作](controls.md#レーンカバーとhs)を参照してください。
- 「選曲画面の 設定 → 表示」では、`CONSTANT FADE`の下に`HS ANIMATION`（HS変更時のアニメーション時間、10ms刻み）と`E2+KEY GREEN INVERT`があります。
- `RULE MODE` / `LN MODE`を変更すると、選曲一覧のスコア・リプレイ・フォルダの集計を新しいスコアの区分ですぐ読み込み直します。変更前のプリロードとリトライ用のキャッシュは破棄します。

「BMZ メニュー → プレイ」または「選曲画面の 設定 → PLAY」では、次の項目をプロファイルごとにON / OFFできます。
すべて既定でOFFで、判定・スコアの保存条件・IRのスコアの区分は変わりません。

| 項目 | ONにしたときの動作 |
| --- | --- |
| RESULT WAIT / BGM・BGAの最終配置までリザルトを待機 | 通常の終了を、最後のノート・BGM・通常のBGAレイヤーの配置から、譜面の時刻で5秒後まで延ばします。PCMファイルの再生の完了を検出する設定ではありません |
| MISSLAYER GOOD CLEAR / GOOD以上でミスレイヤーを解除 | PGREAT・GREAT・GOODでミスBGAをすぐ解除します。次のBAD・POORで再び表示します |
| MISS KEYSOUND / 見逃しPOOR時にキー音を再生 | 打鍵せずに見逃した通常のノート・LNの始点と、離さずに見逃したCN / HCNの終点のキー音を、POORが確定したときに再生します |

- RESULT WAITは、通常プレイ・Autoplay・Replay・コースに適用します。
- プラクティスの区間の終了、Escなどの手動での終了、途中でのFAILEDでは、待機を延ばしません。ミスBGAだけの配置や、使われていない音声の定義でも延ばしません。
- MISS KEYSOUNDは、空POORや早く離したことによるPOORでは追加で鳴らしません。CN / HCNの始点の見逃しによる2つのPOORでは、始点の音だけを鳴らします。
- キー音の自動再生がONの場合は、重ねて再生しません。

### S-RANDOMの補正

「BMZ メニュー → プレイ」の「S-RANDOM 補正」、または「選曲画面の 設定 → PLAY」の`S-RANDOM CORRECTION`で、S-RANDOM / S-RANDOM-EXが同じレーンへの連続を避ける方法を選べます。どちらもSESSION MODEとKEY CONVERSIONの間にあります。
プロファイルごとに`play.s_random_correction`へ保存し、既定はLM 120HZです。

| 選択肢 | 動作 |
| --- | --- |
| OFF (LR2) | 間隔を見ません。同時刻のノーツと押している最中のLNだけを避けるため、どれだけ狭い間隔でも縦連になりえます |
| 40MS (BEATORAJA) | beatorajaと同じく、40ms以内の連続を避けます |
| LM 120HZ | 120Hzのフレーム単位で間隔を測ります。短い間隔の連打が続くほど、広い間隔（6〜8フレーム）まで連続を避けます |

- 変更は次のプレイから反映します。リプレイと「同じ配置でリトライ」は、記録時の方法で配置します。
- どの方法でもスコアの保存条件・IRのスコアの区分は変わりません。

## スキン

- 「対象画面」で選曲・決定・各キーモード・BATTLE・リザルト・コースリザルトのどれかを選び、その対象だけを編集します。選曲・決定・リザルト・コースリザルトは「共通画面」にまとめています。
- オプション / ファイル選択 / 位置・サイズはセクションに分けてすべて表示し、検索欄で全セクションの項目名を絞り込めます。検索語は対象ごとに保持します。
- 「デフォルトに戻す」は、編集中の対象のオプション・素材・位置の調整を初期値へ戻します。
- 「追加スキンのフォルダーを開く」は、現在のデータの保存先の`skins`を開きます。スキンを置いたら「スキン一覧を更新」で読み込み直し、画面ごとに選んでください。
- 選択したスキンの実際のパスと、読み込みのエラーも確認できます。エラーのときは、保存済みの選択・オプションを保持します。
- ライブラリ外のファイルは、パスを指定して「この外部スキンを許可」を押してから読み込みます。許可はそのスキンと実体の親フォルダーに限定され、他のスキンへ共有されません。「外部スキンの許可を解除」で取り消せます。
- 以前から保存していた外部パスも再許可が必要です。ライブラリ内でも、許可範囲外へ向かう子リンクは自動的には許可しません。追加の共有フォルダーと`skin.external_access`の設定は[スキンのファイル参照](skin.md#スキンのファイル参照と外部スキンの許可)を参照してください。
- スキンの設定項目は読めて本体の読み込みだけに失敗した場合は、エラーの下にオプションも表示します。オプションが原因で失敗した場合は、ここで変更すると読み込み直します。設定項目も読めない場合は、オプションを表示しません。

### 同梱antiqueスキンのオプション

「BMZ メニュー → スキン」でプレイスキンにantiqueを選ぶと、次のオプションを変更できます。

| オプション | 値・既定値 |
| --- | --- |
| Ambient | OFF（既定） / ON |
| Ambient表示方式 | 全体（既定） / Spread |
| Spread範囲 (%) | 0〜200%、10%刻み、既定20% |
| Ambientぼかし度 (%) | 0〜100%、10%刻み、既定50% |
| Ambientパネル透明度 | 0〜100%、10%刻み、既定40% |
| 前面BGAの明るさ(-255 ~ 0) | 0が元の明るさ（既定）、-255が黒 |
| 背景/Ambient BGAの明るさ(-255 ~ 0) | 0が元の明るさ（既定）、-255が黒 |
| BPM変化予告 (BMZ) | OFF（既定） / TYPE A（判定文字の上） / TYPE B（判定文字の下） / TYPE C（レーン外・判定文字の横） / TYPE D（レーン外・判定線の横） |
| BPM変化予告タイミング | 500 / 1000 / 1500 / 2000（既定） / 3000 / 4000ms |
| BPM変化予告の表示位置 | x / yで位置、w / hで数字1桁の幅・高さ（「»」と間隔も同じ比率）、aで透明度を調整 |

- SpreadとAmbientの描画、BGAの明るさの適用範囲は[Ambient背景](skin.md#ambient背景bmz拡張)を参照してください。
- BPM変化予告は、`BPM × SCROLL`が変わる指定時間前から直前まで、「153 » 156」のように変化前後のBPM換算値を表示します。STOPは開始時に0、終了時にその位置の値へ変化します。SPEEDは含めません。
- 差の絶対値が1未満の変化は予告しません。0・負値も対象とし、数値が増えるときは青、減るときは赤です。数字はFAST / SLOW数と同じ画像（等倍、最大3桁）で、同梱antiqueでは負値に横棒の負号を付けます。負号は既存画像と同じ11×3pxで、13×13pxの文字枠内に左右各1px・上下各5pxの余白を取り、数字のサイズ設定に合わせて拡縮します。
- TYPE AはFAST / SLOWの表示よりさらに上に表示します。TYPE C / Dは、レーンが画面の左寄りなら右側、右寄りなら左側に、レーン側の数字をレーンのすぐ横へ寄せて表示します。
- 予告の時間は実時間です。再生速度を変えても、同じ秒数前から表示します。
- 表示はLIFTに合わせて上下します。TYPE AはFAST / SLOW、TYPE B / Cは判定文字の表示位置の調整にも合わせて動きます。
- 「BPM変化予告の表示位置」はスキンの読み込み時に反映するため、プレイ中に変えた場合は次のプレイから反映します。
- 参照IDは[BPM変化予告](skin.md#bmz-bpm-change-preview-refs)を参照してください。

## ライブラリ

- 曲フォルダは末尾のフォルダ名を表示し、フルパスはマウスを重ねたときのツールチップに表示します。
- 「ライブラリを再スキャン」は、選曲画面の位置にかかわらず、設定を保存してから全ルートを同期します。
  追加・変更された譜面だけを解析し、サイズと更新日時が変わらない譜面は登録を使い続けます。
- 「すべての譜面を再解析」は、変更のない譜面も含めて全ルートの譜面を解析し直します。
  ファイルの内容だけを書き換えてサイズと更新日時が変わらなかった場合に使います。
- 全体の再スキャンと再解析では、設定から削除したルートの登録も整理します。実際のファイル・スコア・リプレイは削除しません。
- 無効にしたルートや、一時的に読めない設定内のルートの登録は保持します。
- F5と個別のルートの再読み込みは、対象のフォルダまたは書庫だけを、追加・変更された譜面に限って更新します。

CLIの`songs load` / `songs reload`も、対象を指定しない場合は全体の同期です。

- `songs load <PATH>`は部分的な更新です。設定外の場所も、次の全体の同期までは再起動後も使えます。設定ファイルには追加しません。
- 無効に設定した場所は、部分的な更新の後も選曲の対象外です。
- 全体の同期の後も残したい場所は、`songs add <PATH>`で設定に登録してください。

曲root内のZIP / RAR / 7z / tar.gz / LZHは、展開せずにスキャンできます。
隠しファイル・フォルダもbeatorajaと同じく探索します。常に除外する名前は[曲の取得元とスキャン](song-sources.md#走査と更新)を参照してください。
展開の時期、キャッシュ、対応形式と制限は[書庫内譜面の直接再生](archive-songs.md)を参照してください。
Windowsでの高速なファイル探索は[Everything連携](everything.md)を参照してください。

## Linuxのアイドル抑止

Linuxでは、BMZのウィンドウにフォーカスがある間、デスクトップへアイドル抑止を要求します。
コントローラーで操作している間に、スクリーンセーバー・自動ロック・アイドルによる画面の消灯が起きないようにするためです。

- 選曲・設定・リザルト・オートプレイ・リプレイでも有効です。前面で放置している間も抑止します。
- フォーカスを失ったとき、アプリを中断・終了したときに解除し、フォーカスが戻ったときに再び要求します。
- OSの設定は変更しません。手動のロック・明示的なスリープ・ログアウトの禁止は要求しません。
- XDG Desktop PortalのIdle抑止を優先し、使えなければD-BusのScreenSaver APIへ切り替えます。
- 対応するサービスがない場合は、ログに警告を記録して通常どおり動作し、フォーカス中は30秒後に再試行します。
- 抑止の要求・解除は専用のworkerで行い、入力・判定・描画の待機には使いません。

## 互換・移行

- 旧設定のゲームパッドのバックエンド`GameInput`は、読み込み時に`gilrs`へ移行します。
- 旧`Scratch Input Mode`設定は使いません。既存のプロファイルの`scratch_mode`は読み込み時に無視し、次に保存するときに削除します。
- 旧UI actionの`Enter`（`SelectEnter`）と`OptionBga`は非推奨です。プロファイルに残っていても、入力の動作には使いません。
- 未実装のテーマ・終了確認の設定は表示しません。
- 旧版では、1P / 2Pに実機を割り当てていない`gamepad1` / `gamepad2`（と`gamepad3`以降）の行を、接続順の番号の機器として扱っていました。現在は、割り当てのないスロットの行を使いません。3台目以降は割り当てる方法がないため、`gamepad3`以降の行は使いません。
- 共通のE1〜E4の`CONTROLLER 1P` / `CONTROLLER 2P`で「解除」した側は、プロファイルに`control = ""`の行として保存します。旧版はこの行を読みません。
- コントローラーのレーンを「解除」した場合も、`control = ""`の行として保存します。以前の版で解除したレーンは行がないため、「設定なし」として読みます。旧版は`control = ""`の行を読みません。
- 以前の版では、選曲画面の2Pのコントローラーは、押したボタンが14Kの割り当てになければ、7Kの割り当てをボタン名で探していました。そのため14Kの2P KEY1を変えても、7KのKEY1のボタンが2PのKEY1として残りました。現在は、レーンごとに使う割り当てを決めてから探します。1Pのコントローラーも同じく、7Kにそのレーンの設定がないときだけ14Kの1P側を使います。
